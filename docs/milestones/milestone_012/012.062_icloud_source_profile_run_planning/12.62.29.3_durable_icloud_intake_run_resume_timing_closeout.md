# 12.62.29.3 Durable iCloud Intake Run Resume Timing Closeout

Date: 2026-07-06

## Outcome

Implemented the 12.62.29.3 durability hardening for iCloud Intake.

The normal UI import path now uses explicit `/intake/` endpoints and advances one durable chunk at a time. Completed chunks are committed before the next chunk begins, interrupted runs can become `resume_available` without manual DB repair, and unsafe Source Intake/cleanup states stop as `stopped_needs_review` with chunk-level counters and reasons.

No live iCloud operation was run during this closeout.

## Operator Behavior

Expected normal flow after this change:

```text
Refresh / Prepare Next 1000
Import Next 1000
  start durable import run
  advance chunk 1
  persist chunk result
  advance next chunk
  continue until completed, review-stopped, or resumable interrupted
```

If the browser/backend/request stops between chunks, status refresh can mark the run `resume_available`. The operator must explicitly press `Resume Interrupted Import` before more acquisition/Source Intake/cleanup work starts.

If the process stops after imported files/resources but before verified cleanup, the run is not auto-resumed. It is marked for review so cleanup/staging safety can be verified first.

## Post-Implementation Refresh Fix

The first fresh UI refresh attempt returned `Failed to fetch` after a long metadata-only scan. Backend output showed a duplicate inventory identity:

```text
source_profile_id=66
remote_identity_basis=helper_item_id_observed_stable
remote_identity=AZkMOK6EBV3AegbQW4/Qnq9p17uq
```

The helper listing contained a repeated stable `item_id` in the same response. Because inventory scan autoflush is disabled, the second occurrence could not see the first pending insert and PostgreSQL rejected the final flush.

Follow-up fix:

```text
metadata-only inventory scan dedupes repeated helper identities within a single listing
duplicate helper observations no longer create duplicate pending inserts
regression test added for duplicate identity inside one listing
```

This fix changes metadata inventory refresh only. It does not run or alter acquisition, download, staging, Source Intake, Vault writes, or cleanup.
