# 12.62.29.1 Ingestion Page iCloud Run Workflow Report

Date: 2026-07-03

## Summary

Implemented a focused Ingestion-page iCloud Source Workflow for normal operator runs. The workflow lets an operator select an active iCloud source profile, refresh metadata-only inventory, preview a bounded historical backfill, run historical backfill with Source Intake enabled, and review skipped/deferred ledger rows.

No live iCloud acquisition, cleanup execution, Source Intake run, Vault write, scheduler, commit, push, reset, rebase, merge, tag, checkout, or stash was performed during this implementation.

## UI Behavior

- Added `IcloudRunWorkflowPanel` to the Ingestion page.
- Historical mode is enabled as `Continue Historical Backfill`.
- `Import New iCloud Photos` is visible but disabled as Coming Soon.
- Limit is a free-form positive integer input.
- Historical default limit is `500`; New Import default is reserved as `100`.
- Candidate search cap is fixed at `1000` and displayed as operational context.
- Preview calls `/api/admin/icloud-backfill/acquire-preview` with `include_items=true`.
- Run calls `/api/admin/icloud-backfill/acquire` with `dry_run=false`, `auto_run_source_intake=true`, and `include_items=true`.
- After acquisition, the UI starts cleanup dry run and only calls guarded cleanup execute when safe eligible cleanup relative paths exactly match the just-completed acquired relative paths and all safety counters are zero.
- If exact-match cleanup safety cannot be proven, the UI stops after cleanup dry run and shows `Import completed, cleanup needs review.`
- Deferred detail loads safe rows from `/api/admin/source-profiles/{source_id}/deferred-assets?state=active_deferred&limit=100`.

## Backend Support

- Raised historical backfill acquire limit validation cap from `1000` to `10000`.
- Kept candidate listing cap behavior unchanged.
- Added safe cleanup dry-run/status `eligible_files` projection.
- Safe cleanup eligible fields are limited to relative path, size, hashes already present in cleanup manifest, verification state, and safe asset id if present.
- Absolute filesystem paths, Vault paths, credentials, tokens, URLs, helper payloads, and Apple identifiers are not exposed through the new `eligible_files` projection.

## Admin Behavior

Admin iCloud controls were left in place and marked as legacy/internal. Normal iCloud runs now point operators to the Ingestion page.

## Follow-Up Cleanup Review Fix

After a UI run for source `66`, the operator saw `Import completed, cleanup needs review.` The run itself was successful:

- acquisition run id: `62`
- acquisition batch id: `38`
- source intake run id: `86`
- imported logical items: `96`
- imported resources: `98`

Root cause: the UI compared cleanup eligible paths against only logical-item primary paths from the acquire response. The batch included two Live Photo companion resources, so cleanup had `98` resource paths while the UI could prove only `96` primary paths.

Fixes added:

- acquire response now exposes safe `acquired_resource_paths`.
- UI cleanup matching now uses all acquired resource paths.
- cleanup review state now shows the specific reason, dry-run id, eligible count, verification failures, unexpected files, and operator-safe `Refresh Cleanup Review` / `Execute Guarded Cleanup` controls.
- cleanup authorization fingerprint now ignores volatile staged mtime while preserving path, size, staged hash, asset hash, Vault hash, and final pre-delete revalidation.
