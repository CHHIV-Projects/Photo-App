# Milestone 12.62.28.4 - Historical Backfill Execution Operator Validation Runbook

## 1. Purpose

This runbook validates the backend historical iCloud backfill execution path added in 12.62.28.3 with tiny, operator-controlled limits.

The safe validation order is:

1. Confirm the backend and Source Profile state.
2. Confirm historical inventory exists.
3. Run preview-only calls.
4. Prepare a tiny real execution command.
5. Run `dry_run=false` only after explicit approval of the exact command, exact `source_id`, and exact limit.

This runbook does not add or require Admin UI, scheduler automation, cleanup automation, Source Intake bypasses, remote deletion, or direct Vault writes.

## 2. Preconditions

Before starting:

- Use branch `feature/icloud-final-routine`.
- Confirm 12.62.28.3 is present in the current branch.
- Confirm the backend is configured for the intended local/dev environment.
- Confirm the target Source Profile is active and is an iCloud `cloud_export` profile using `icloudpd`.
- Confirm a 12.62.27 inventory scan has already been run for the same Source Profile.
- Confirm no other iCloud acquisition, Source Intake, or cleanup operation is active for the same source.
- Confirm the managed iCloud staging path is the intended local staging/export path.
- Do not run any `dry_run=false` request until the product owner explicitly approves the exact command.

Recommended read-only Git checks:

```powershell
git branch --show-current
git status --short
git log --oneline --decorate -5
```

## 3. Confirm Backend Is Running

Set the base URL once:

```powershell
$baseUrl = "http://localhost:8001"
```

Check service health:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/health" | ConvertTo-Json -Depth 8
```

Expected:

- `status` is `ok` or otherwise explainable for local dev.
- `database` is `ok`.
- No secrets, tokens, passwords, or Apple credentials are returned.

Optional Admin summary smoke check:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/summary" | ConvertTo-Json -Depth 8
```

Stop if the backend is not reachable or the database is unreachable.

## 4. Identify `source_id`

List active Source Profiles:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/source-profiles?status=active&include_username=false" |
    ConvertTo-Json -Depth 10
```

Pick the iCloud profile where:

- `source_type` is `cloud_export`
- `cloud_provider` is `icloud`
- `acquisition_method` is `icloudpd`
- `profile_status` is `active`
- `managed_staging_path` is present and correct

Set the chosen ID:

```powershell
$sourceId = <SOURCE_ID>
```

Inspect the selected profile:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/source-profiles/$sourceId" |
    ConvertTo-Json -Depth 10
```

Check iCloud readiness:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/source-profiles/$sourceId/icloud-readiness" |
    ConvertTo-Json -Depth 10
```

Stop if the Source Profile is ambiguous, not active, not iCloud, missing its account username, missing its managed staging path, or not ready for a reason you cannot explain.

## 5. Confirm Inventory Exists

Call the historical backfill status endpoint:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/icloud-backfill/status?source_id=$sourceId" |
    ConvertTo-Json -Depth 10
```

Expected:

- `current.status` exists.
- `current.inventory_total_count` is greater than `0`.
- `current.eligible_metadata_count` is greater than `0` for an acquisition test.
- `current.stop_reason` is explainable.

Stop if the status endpoint returns `404`, inventory is missing, eligible count is zero, or the state indicates a failed or blocked inventory condition.

## 6. Step 1: Acquire Preview / Dry-Run Validation

This call must not download files, stage files, run Source Intake, mark inventory complete, or write to Vault.

```powershell
$previewBody = @{
    source_id = $sourceId
    acquire_limit = 1
    max_listing_candidates = 1000
    include_items = $true
} | ConvertTo-Json

$preview = Invoke-RestMethod `
    -Method Post `
    -Uri "$baseUrl/api/admin/icloud-backfill/acquire-preview" `
    -ContentType "application/json" `
    -Body $previewBody

$preview | ConvertTo-Json -Depth 12
```

Expected safe output:

- `status` is `preview_completed`.
- `selected_inventory_count` is `1` or explainably `0`.
- `preview_selected_logical_count` and `preview_selected_resource_count` match the selected item.
- `preview_items` includes only safe item summaries when `include_items=true`.
- `next_safe_action` is usually `review_preview`.
- No download, staging, Source Intake, completion update, cleanup, or Vault write occurs.

Stop if the preview returns stale-only rows, unsafe/partial Live Photo evidence, unexpected skipped counts, or a response that implies real acquisition work happened.

## 7. Step 2: Acquire Endpoint With `dry_run=true`

This validates the execution endpoint while keeping the same safety boundary as preview.

```powershell
$dryRunBody = @{
    source_id = $sourceId
    acquire_limit = 1
    max_listing_candidates = 1000
    dry_run = $true
    auto_run_source_intake = $true
    include_items = $true
} | ConvertTo-Json

$dryRun = Invoke-RestMethod `
    -Method Post `
    -Uri "$baseUrl/api/admin/icloud-backfill/acquire" `
    -ContentType "application/json" `
    -Body $dryRunBody

$dryRun | ConvertTo-Json -Depth 12
```

Expected safe output:

- `dry_run` is `true`.
- `status` is `dry_run_preview`.
- `downloaded_logical_count` is `0`.
- `downloaded_resource_count` is `0`.
- `source_intake_attempted` is `false`.
- `source_intake_succeeded` is `false`.
- `acquisition_run_id`, `acquisition_batch_id`, and `source_intake_run_id` are `null`.
- `backfill_completed_count` is `0`.
- `next_safe_action` is usually `run_acquire_with_dry_run_false`.

Compare the preview and dry-run responses:

```powershell
[pscustomobject]@{
    PreviewSelectedInventory = $preview.selected_inventory_count
    DryRunSelectedInventory = $dryRun.selected_inventory_count
    PreviewLogical = $preview.preview_selected_logical_count
    DryRunLogical = $dryRun.selected_logical_count
    PreviewResources = $preview.preview_selected_resource_count
    DryRunResources = $dryRun.selected_resource_count
    PreviewStale = $preview.skipped_stale_count
    DryRunStale = $dryRun.skipped_stale_count
} | ConvertTo-Json -Depth 4
```

Stop if `dry_run=true` downloads, stages, runs Source Intake, marks completion, or materially disagrees with `acquire-preview` without an explainable listing change.

## 8. Step 3: Gated Tiny `dry_run=false` Run

Do not run this command until the product owner approves:

- exact `$baseUrl`
- exact `$sourceId`
- exact `acquire_limit = 1`
- exact `max_listing_candidates = 1000`
- exact `dry_run = $false`
- exact `auto_run_source_intake = $true`

Prepared command:

```powershell
$executeOneBody = @{
    source_id = $sourceId
    acquire_limit = 1
    max_listing_candidates = 1000
    dry_run = $false
    auto_run_source_intake = $true
    include_items = $true
} | ConvertTo-Json

$executeOne = Invoke-RestMethod `
    -Method Post `
    -Uri "$baseUrl/api/admin/icloud-backfill/acquire" `
    -ContentType "application/json" `
    -Body $executeOneBody

$executeOne | ConvertTo-Json -Depth 12
```

Expected if approved and run:

- `dry_run` is `false`.
- `selected_inventory_count` is at most `1`.
- `selected_logical_count` is at most `1`.
- `downloaded_resource_count` is bounded to the selected logical item resources.
- `acquisition_run_id` and `acquisition_batch_id` are present if acquisition started.
- `source_intake_attempted` is `true` only when the durable batch is ready for Source Intake.
- `source_intake_succeeded` is `true` before `backfill_completed_count` becomes `1`.
- Files stage only through the Source Profile managed staging path.
- Source Intake remains the only path to Vault, asset, provenance, or canonical metadata writes.
- Cleanup remains separate and review-controlled.

Important caution: in the 12.62.28.3 synchronous execution path with `auto_run_source_intake=true`, Source Intake results are mapped back to inventory rows by the durable batch item order created from the selected inventory order. This is acceptable for this immediate, in-process validation path. If `auto_run_source_intake=false`, no inventory row should be marked `backfill_completed`; later completion or reconciliation requires a future stronger persistent inventory-to-batch mapping or an explicit follow-up milestone.

## 9. Step 4: Inspect Source Intake Result and Inventory State

Start with the execution response:

```powershell
$executeOne | ConvertTo-Json -Depth 12
```

Record these fields:

- `status`
- `stop_reason`
- `next_safe_action`
- `selected_inventory_count`
- `matched_listing_count`
- `selected_logical_count`
- `selected_resource_count`
- `downloaded_logical_count`
- `downloaded_resource_count`
- `source_intake_attempted`
- `source_intake_succeeded`
- `source_intake_run_id`
- `acquisition_run_id`
- `acquisition_batch_id`
- `backfill_completed_count`
- `items`

Refresh inventory status:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/icloud-backfill/status?source_id=$sourceId" |
    ConvertTo-Json -Depth 10
```

Refresh the Source Profile detail:

```powershell
Invoke-RestMethod -Method Get -Uri "$baseUrl/api/admin/source-profiles/$sourceId" |
    ConvertTo-Json -Depth 10
```

If the API response includes `source_intake_run_id`, inspect the latest Source Intake report or logs using the repo's normal operator process for Source Intake reports. Paste back the run ID, report filename/path if available, and count summary.

If API output is not enough to verify inventory row state, use a read-only database inspection through the app environment. Do not edit DB rows manually. The exact DB tooling depends on the local environment; collect only:

- inventory row `id`
- `backfill_completed`
- `backfill_resolution_state`
- `acquisition_state`
- `acquisition_run_id`
- `acquisition_batch_id`
- `source_intake_run_id`
- `last_error_code`
- `last_error_message`

## 10. Step 5: Optional Tiny Follow-Up Run, `acquire_limit=5`

Only after the `acquire_limit=1` real execution is reviewed and explicitly approved, prepare a second tiny run:

```powershell
$executeFiveBody = @{
    source_id = $sourceId
    acquire_limit = 5
    max_listing_candidates = 1000
    dry_run = $false
    auto_run_source_intake = $true
    include_items = $true
} | ConvertTo-Json

$executeFive = Invoke-RestMethod `
    -Method Post `
    -Uri "$baseUrl/api/admin/icloud-backfill/acquire" `
    -ContentType "application/json" `
    -Body $executeFiveBody

$executeFive | ConvertTo-Json -Depth 12
```

Do not run this until the operator has reviewed:

- the `acquire_limit=1` execution response,
- Source Intake outcome,
- inventory completion behavior,
- staging folder contents,
- logs/reports,
- and any cleanup decision.

## 11. Expected Safe Outputs

For `acquire-preview`:

- no downloads,
- no staging,
- no Source Intake,
- no inventory completion updates,
- count-focused preview response.

For `acquire` with `dry_run=true`:

- no downloads,
- no staging,
- no Source Intake,
- no inventory completion updates,
- no run/batch/intake IDs,
- response mirrors preview selection counts.

For approved `acquire` with `dry_run=false` and `auto_run_source_intake=true`:

- files may download only to managed iCloud staging,
- durable acquisition run/batch IDs should be returned if acquisition starts,
- Source Intake may run only after durable staging is ready,
- inventory completion may be set only after Source Intake resource success,
- Source Intake remains the only Vault/provenance/asset-writing path.

## 12. Stop Conditions

Stop immediately if any of these occur:

- `dry_run=true` causes download, staging, Source Intake, or completion updates.
- Preview and `acquire` with `dry_run=true` disagree unexpectedly.
- `source_id` is ambiguous.
- Inventory status is missing, failed, or blocked.
- Eligible inventory count is zero.
- Preview returns stale/missing rows only.
- A Live Photo manifest appears partial or unsafe.
- Real execution response lacks `acquisition_run_id` or `acquisition_batch_id` when acquisition was expected to start.
- Source Intake fails or is blocked.
- An inventory row is marked complete before Source Intake success.
- Cleanup appears to run automatically without review.
- Any remote iCloud deletion behavior appears.
- Any Vault write appears outside Source Intake.
- A large run is accidentally prepared or attempted.
- Any command includes `dry_run=false` without explicit approval.

## 13. Rollback and Retry Guidance

Do not manually edit inventory, acquisition, Source Intake, asset, provenance, or Vault state as a rollback.

For dry-run failures:

- rerun status and readiness checks,
- confirm the Source Profile,
- rerun inventory scan only if the operator approves it,
- review logs for validation errors.

For approved tiny execution failures:

- stop after the first failure,
- collect the execution response,
- collect backfill status,
- collect acquisition run/batch IDs if present,
- collect Source Intake run/report details if present,
- inspect managed staging path contents before any cleanup,
- use the existing cleanup runbook only if cleanup is explicitly approved.

Retry only after the failure mode is understood. Prefer another `acquire_limit=1` run before any larger follow-up.
