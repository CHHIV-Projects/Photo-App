# Milestone 12.62.28.7 - Source Profile Deferred Asset Ledger Report

## 1. Ledger Purpose

Added a durable source-profile-level deferred asset ledger so remote assets that are observed but not acquired remain searchable, countable, and reprocessable later.

The immediate driver is adjusted iCloud resources. Adjusted resources remain non-eligible for acquisition, but they are now represented as deferred remote assets instead of only appearing as skipped inventory rows.

## 2. Schema/Model Design

Added generic source-profile models:

```text
backend/app/models/source_profile_deferred_asset.py
```

Tables:

```text
source_profile_deferred_assets
source_profile_deferred_asset_events
```

Current-state uniqueness:

```text
source_profile_id + remote_identity_basis + remote_identity + deferred_category
```

`inventory_id` is a nullable reference field and is not part of identity.

Schema sync lives in:

```text
backend/app/services/source_profile_deferred_asset_schema.py
```

The schema is also ensured from app startup and from the iCloud backfill schema path for direct test/service use.

## 3. Current-State Versus Event-History Behavior

Current-state rows track the latest known deferral state:

```text
first_seen_at
last_seen_at
first_seen_run_id
last_seen_run_id
last_changed_at
observation_count
current_state
policy_status
deferred_category
deferred_reason_code
safe_metadata_json
```

Event rows are append-only transition records:

```text
first_deferred
reason_changed
classification_changed
```

If an item becomes eligible/non-deferred on a later scan, the active deferred row is marked:

```text
current_state = no_longer_deferred
```

and a `classification_changed` event is appended.

## 4. How Duplicate Event Spam Is Avoided

Repeated unchanged observations update only:

```text
last_seen_at
last_seen_run_id
observation_count
```

They do not append duplicate per-asset events.

`unsupported_reasons_json` is parsed, sorted, de-duplicated, and serialized deterministically before meaningful-change comparison.

## 5. Which Rows Are Recorded In This Milestone

The iCloud backfill inventory scan now records all currently observed non-eligible rows that map safely.

Approved mappings:

| source condition | deferred category |
| --- | --- |
| `unsupported_adjusted_resource` | `adjusted_resource_deferred` |
| `identity_ambiguous=true` with no clearer reason | `ambiguous_metadata_deferred` |
| non-empty non-adjusted `unsupported_reasons_json` | `unsupported_metadata_deferred` |
| `eligibility_state=pending_classification` | `pending_classification_deferred` |
| conservative fallback | `unknown_deferred` |

Eligible rows are not made deferred. If a previously deferred remote identity is observed again as eligible, its active deferral is closed as `no_longer_deferred`.

## 6. How Adjusted Resources Are Represented

Adjusted iCloud rows use:

```text
deferred_category = adjusted_resource_deferred
deferred_reason_code = unsupported_adjusted_resource
policy_status = deferred_pending_policy
current_state = active_deferred
```

The ledger does not make adjusted resources eligible and does not import them.

## 7. JSON Report Behavior

Each inventory scan writes a safe JSON summary report under:

```text
storage/logs/deferred_asset_reports/
```

Report fields include:

```text
source_profile_id
run_id
run_kind
generated_at
total_deferred_seen
new_deferred_count
changed_deferred_count
unchanged_deferred_count
resolved_count
by_category
by_reason_code
safe_sample_rows
adjusted_resource_deferred_count
adjusted_single_resource_count
adjusted_live_photo_grouped_count
report_version
```

The report uses allowlisted safe metadata only. It does not include helper IDs in API samples, credentials, tokens, cookies, signed URLs, Apple account identifiers, or raw CloudKit/helper payloads.

## 8. API/Status Behavior

Existing iCloud backfill status now includes:

```text
deferred_current_count
deferred_adjusted_resource_count
deferred_ambiguous_count
deferred_unsupported_count
deferred_new_since_last_scan_count
deferred_changed_since_last_scan_count
```

Added bounded list endpoint:

```text
GET /api/admin/source-profiles/{source_id}/deferred-assets
```

Supported query params:

```text
limit default 100, max 500
category optional
reason_code optional
state optional
```

Returned rows expose only safe operator fields such as path, extension, content type, grouping, category, reason, policy status, current state, and observation timestamps/counts.

## 10. Known Limitations

- Population is currently driven by iCloud backfill inventory scans.
- The ledger does not store raw helper payloads.
- The list endpoint is read-only and backend-only; no Admin UI was added.
- `no_longer_observed` is not implemented for rows absent from a later bounded helper listing.
- `resolved` as imported is not set by this milestone; import resolution must come from future acquisition/Source Intake evidence.

## 11. Follow-Up Recommendations

- Add Admin UI surfacing only after the backend ledger is reviewed.
- Consider a later `no_longer_observed` state once bounded listing semantics are product-approved.
- If adjusted-resource policy changes, use the ledger to re-query affected identities and transition rows through an approved acquisition policy.
