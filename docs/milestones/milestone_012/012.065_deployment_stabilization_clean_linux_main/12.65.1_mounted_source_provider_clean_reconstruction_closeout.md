## 4. Final Mounted Source Provider Architecture

Status: **implemented; confirmed by focused tests; live host validation
required**.

```text
allowlisted Linux-mounted location
-> non-root host identity broker
-> linux_stable_mount_v1
-> Access Node / Source Endpoint / Source Profile
-> readiness re-probe
-> Source Selection re-probe
-> backend-derived container Runtime Root
-> dispatch re-probe
-> unchanged start_source_intake
-> existing Source Intake / Vault / Asset / provenance
```

The internal versioned provider identifier remains
`linux_stable_mount_v1`. Product and operator documentation describes its
architectural role as the Mounted Source Provider.

Host Observed Path, container Runtime Root, and durable Source identity remain
separate.

## 5. Provider Separation from Windows Helper and iCloud

Status: **implemented; confirmed by focused Windows/fixture regressions and
static frontend review**.

The Mounted provider accepts only Local and NAS locations explicitly supplied
through its Linux provider contract. It does not accept External, Removable, or
Optical types and does not translate Windows paths.

The existing Windows provider remains independently selectable. The controlled
Linux fixture provider remains independently selectable. iCloud remains on its
existing independent workflow and no iCloud implementation file was changed.

The frontend shows External, Removable, and Optical choices on the Linux
runtime but disables them with Source-oriented wording:
`Not available from this server yet`. Existing Windows code remains present
for a runtime where the Linux Mounted capability endpoint is unavailable.

Mounted-location discovery is represented as an explicit capability state and
is used only for Mounted Local/NAS creation. It is not a universal filesystem
mode switch.

## 6. POSIX and Root Containment Implementation

Status: **implemented and confirmed by focused tests**.

The POSIX mapping layer:

- requires non-root normalized absolute host and runtime slots;
- treats relative roots as case-sensitive;
- rejects absolute input, NUL, empty components, `.`, and `..`;
- rejects backslashes instead of translating them;
- derives host and runtime paths separately;
- requires exact containment under each configured slot;
- requires broker-returned host/runtime paths to equal backend re-derivation.

The broker performs a second realpath-based containment/readability check and
blocks symlink escape and slot substitution.

Existing Windows path handling was not changed.

## 7. Broker and Client Implementation

Status: **implemented and confirmed by focused tests; live socket validation
required**.

The application client and host broker use protocol version 1 with:

- one bounded JSON object per line;
- maximum request/response size of 256 KiB;
- fixed timeouts;
- exact action fields and unknown-field rejection;
- opaque allowlisted location IDs;
- sanitized blockers and evidence;
- fixed no-shell subprocess argument lists;
- no arbitrary path, Source-byte, mount, Docker, or ingestion authority.

The tracked broker refuses to run as root. Its systemd unit uses a dedicated
user/group, an AF_UNIX-only network boundary, protected filesystem settings,
and a mode-0660 group-controlled socket.

## 16. Namespace and Host/Runtime Tracked Assets

Status: **implemented and confirmed by unit/static tests; live validation
required**.

The clean namespace mechanism contains one final topology:

```text
verify exact authority and Local backing
-> accept one exact pre-existing shared namespace/slot, or
-> self-bind exact namespace if absent
-> make namespace private
-> prove NAS slot absent
-> bind exact authority to exact slot
-> validate exact unique slot
-> make namespace shared
-> validate namespace and slot again
```

It rejects duplicate, ambiguous, wrong-source, wrong-filesystem,
wrong-major/minor, wrong-root, and wrong-propagation rows.

Rollback removes only invocation-created slot/root mounts in reverse order. A
pre-existing namespace is restored to shared propagation and is never
unmounted. The authoritative NAS target is never passed to `umount`.

The clean script is 352 lines versus 683 at the frozen tip. Its focused test is
151 lines versus 853 historically. Intermediate implementations and historical
diagnostic ceremony were not retained.

Compose adds only:

- two numeric supplemental GIDs;
- fixed read-only `/mnt/photo-organizer-sources -> /app/sources` with
  `rslave`;
- fixed read-only broker-directory exposure.

There is no broad mount, privileged backend, Docker socket, Test change, or
automatic activation.
