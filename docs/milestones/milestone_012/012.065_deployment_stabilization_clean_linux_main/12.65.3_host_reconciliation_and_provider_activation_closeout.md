## 20. Deviations

Confirmed by gate and Product Owner direction.

### Approved namespace safety correction

Before namespace activation, review found that the initially reconstructed namespace script unconditionally ran install -d against NAS_SLOT. Because the live slot was already a CIFS mount, that could have modified the mounted share root.

Execution stopped before namespace start. The Product Owner approved the smallest tracked correction and focused tests. Existing exact/wrong/duplicate slot states now branch from mount-table evidence before any slot filesystem operation; only a confirmed absent slot may receive local mountpoint preparation. The authoritative NAS target is never passed to install, chmod, chown, or umount.

### Broker activation evidence correction

The first authorized broker activation block successfully ran systemctl start. Its immediate post-start sampling raced Type=simple initialization and checked the listener through host /proc/net/unix despite PrivateNetwork=true. This produced false negatives for transient process/socket readiness and namespace-scoped listener ownership.

The Product Owner supplied terminal history, proving the first block was the activation source. The second execution correctly stopped at preflight and did not start the service again. A corrected read-only check used /proc/MAINPID/net/unix and passed without restart or repair.

### Harmless pasted-output shell input

Some broker gate output was accidentally pasted into the interactive shell. The history showed only temporary shell variable assignments and a command-not-found result. No sudo command, service operation, file change, mount operation, or Docker action resulted.

### Repository editing tool fallback

The normal patch helper was unavailable because its sandbox helper failed while creating loopback state. The same bounded repository patches were applied with git apply. No scope expansion resulted.
