## 6. REVISE Findings

### Provider boundary

Treat `linux_stable_mount_v1` as the Linux implementation of the **Mounted Source Provider**, not as the generic answer for every filesystem Source. Current supported mounted locations may remain Linux server-local storage and the exact mounted NAS share. External, Removable, and Optical media accessible only from Windows belong to the future Windows Source Helper Provider.

### Creation and UI

Creation should select an explicit server-issued Mounted location and contained relative root. It must not infer provider class solely because the backend OS is Linux or because the location endpoint exists. The frontend should not hide the future Windows Helper architecture behind a Linux-runtime fallback. It should present current Mounted Local/NAS choices and keep Windows Helper Source types separately unavailable until that future arc.

### Readiness, selection, and dispatch

Retain the persisted-location and immediate-reprobe pattern. Reconstruct it as the smallest provider-specific branch around existing services. Dispatch must finish at the unchanged Source Intake seam and must pass:

```text
ingestion_source_id = selected Source Profile ID
runtime_source_root_path = verified container Runtime Root
selection_verified_identity = true
```

Add an explicit Mounted Source regression assertion for these values and retain the 12.64 hardening suite.

### Namespace and deployment assets

Retain only the final required allowlisted namespace, exact NAS-slot identity, read-only container exposure, and fail-closed rollback behavior. Do not carry forward the historical Gate C diagnostic narrative as product architecture. The frozen closeout records that the final topology retry had not yet passed, so exact final host behavior remains a later validation requirement even though the Product Owner lock-in establishes that key namespace/broker behavior was proven during correction.

### Operator behavior

Mounted Source failure should produce a scoped Source-access failure. Development application/storage recovery remains distinct. Do not let an unavailable optional provider silently trigger broad Docker, NAS, mount, or container repair.
