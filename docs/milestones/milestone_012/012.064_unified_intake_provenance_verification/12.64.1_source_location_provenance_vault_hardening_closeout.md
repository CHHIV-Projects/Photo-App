## 6. Selected Source Profile Propagation

Status: **confirmed by code and automated test; confirmed live for unchanged roots**

`PipelineContext` now accepts an optional authoritative `ingestion_source_id`.

For selected modern filesystem Sources:

1. Source Selection and readiness continue to resolve/verify the Runtime Root.
2. Source Intake passes the selected Source Profile ID to the pipeline.
3. ingestion-context resolution loads that existing `IngestionSource` directly.
4. `IngestionRun.ingestion_source_id` uses the selected Profile ID.
5. `IngestionRun.from_path` uses the current resolved Runtime Root.
6. provenance uses the same selected Profile ID and current Runtime Root.
7. the saved Source Profile root is not rewritten.

Modern selected-source handling is limited to Profiles with both endpoint linkage
and an endpoint-relative root. Established legacy/path-only entry points retain the
existing label/type/path compatibility fallback.

## 8. Exact-Known Vault Protection

Status: **confirmed by code, automated test, and live validation**

Before Vault storage, the orchestrator loads existing Assets for candidate
SHA-256 values and supplies canonical Vault state to the storage stage.

For an exact-known SHA:

- the canonical `Asset.vault_path` is authoritative;
- the ordinary Vault-copy helper is not called;
- the canonical path must be non-empty and a readable regular file;
- its size must agree with the Asset and observed candidate;
- its SHA-256 must match;
- successful validation returns the existing canonical path with
  `copy_performed=False`;
- persistence can add legitimate Source provenance without rewriting the Asset or
  canonical Vault file.

Conflict classifications include:

```text
existing_asset_vault_conflict
untracked_vault_path_conflict
```

On conflict:

- the candidate fails;
- no canonical overwrite/reconstruction occurs;
- no successful new provenance is created;
- failure evidence remains available to the pipeline/run report.

No broad Vault repair or historical scan was added.

were Live Photos.

The 165-resource maximum effect was disclosed before Import and the Product Owner
explicitly approved it. The actual durable result was 163 new Assets/Vault files
and 165 provenance rows. No test data was deleted or rolled back.

The first Prepare attempts encountered the isolated iCloud helper's controlled
`reauthentication_required` state. `RunIngestionDispatchService._dispatch_icloud`
did not catch the helper exception, so the API returned HTTP 500 and the browser
showed `Failed to fetch`.

The correct isolated helper was authenticated and validation continued. Error
translation was not changed because authentication/session handling and dispatch
redesign were outside this milestone.
