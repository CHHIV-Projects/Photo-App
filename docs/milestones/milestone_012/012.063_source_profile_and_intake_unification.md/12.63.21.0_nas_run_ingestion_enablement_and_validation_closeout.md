## 3. Final NAS Operator Workflow

For a current-format NAS Source:

1. Create or use a NAS Source through the normal Source workflow.
2. Select Source Type `NAS`.
3. Select the NAS device/share and Source.
4. Click `Select Source`.
5. Backend Source Selection verifies canonical NAS identity and resolves the UNC Source Root.
6. Step 3 shows the normal `Filesystem Source Intake` tile.
7. `Run Ingestion` dispatches through `POST /api/admin/run-ingestion/dispatch`.
8. Backend revalidates Source Selection and NAS runtime-root safety.
9. Existing Source Intake launches through the runtime-root bridge.
10. Existing Source Intake progress, stop, result, and report behavior apply.

## 5. NAS Identity and Path Rules

NAS dispatch now validates:

- selected source is active;
- linked endpoint exists;
- linked endpoint is active;
- linked endpoint type is `nas`;
- selected endpoint ID still matches the Source Profile endpoint;
- selected identity is matched;
- resolved endpoint path is a valid UNC server/share;
- resolved Source Root is a valid UNC path;
- resolved Source Root matches the backend Source Profile endpoint-relative root;
- resolved Source Root remains within the selected server/share boundary;
- `..` traversal segments in the endpoint-relative root are rejected.

NAS execution authority is the canonical UNC runtime root, for example:

```text
\\HENDERSON-NAS\Photos\Camera imports
```

Mapped drive paths are not used as durable authority. A stored mapped path is not rewritten or used when selected-source revalidation supplies the canonical UNC root.

The implementation does not persist the runtime root merely because it was used for launch. It does not update:

- `source_root_path`;
- endpoint identity;
- observed paths;
- aliases;
- endpoint-relative root.

The existing Source Intake run/report path evidence may still record the actual runtime root where already supported.

## 6. Readiness and Failure Behavior

Available current-format NAS:

- selected through Source Selection;
- passes NAS dispatch validation;
- launches existing Source Intake through the runtime-root bridge.

Unavailable or invalid NAS:

- if Source Selection cannot select the NAS Source, dispatch returns the existing blocked/not-selected response and does not launch;
- server-only UNC endpoint paths are blocked;
- non-UNC runtime roots are blocked;
- different-share runtime roots are blocked;
- traversal outside the share boundary is blocked;
- inactive Source Profiles are blocked;
- inactive or missing endpoints are blocked;
- operation conflicts remain blocked by the existing guardrail;
- unreadable/missing roots are blocked by Source Selection and Source Intake readiness/launch checks.

Permission denied:

- no credentials are requested or stored;
- if Windows/app runtime cannot read the UNC Source Root, the run is blocked before launch or fails safely through existing Source Intake behavior.

Network interruption:

- no new recovery or resume infrastructure was added;
- Source Intake remains non-mutating toward source files;
- any mid-run unreadable files remain governed by existing Source Intake failure/report behavior.
