## Background / Context

Milestone `12.63.0` identified that current Source Profiles are stored in `ingestion_sources`, and that `ingestion_sources` currently mixes user-facing Source Profile, backend source registry, and provenance/run anchor behavior.

Milestone `12.63.1` defined the desired boundary model:

```text
Durable Source Endpoint
  = source type + durable identity evidence + immutable alias + observed path history

Source ID / Source Profile
  = durable endpoint + selected root/folder + intake settings + lifecycle state

Observed Path
  = current access path used at setup or run time
  = not durable identity

Ingestion Source / Source Registry
  = current compatibility layer used by Source Intake, iCloud Intake, reports, and provenance
```

The `12.63.1` design recommended the smallest safe future implementation path:

```text
1. Keep ingestion_sources.id as the current operational Source ID / Source Profile ID.
2. Add durable endpoint identity beside ingestion_sources, not in place of it.
3. Add observed path history as append-only evidence.
4. Link new endpoint identity to current Source Profiles when confidence is high.
5. Keep existing provenance source/path/run semantics intact.
6. Use endpoint verification during readiness and run launch for enrolled non-cloud sources.
```

Before schema or UI implementation, this milestone should answer:

```text
What identity evidence can Windows actually provide reliably and safely?
```

## Product Decisions Already Locked

Do not reopen these unless evidence proves they are impractical or unsafe.

### Source Types

Use the v1 source type model:

```text
Local
External Device
Removable Media
NAS
Cloud
```

Definitions:

```text
Local
= folder/path on the current computer, such as C:\Photos or Desktop.

External Device
= physically connected storage whose device/volume is the durable source identity,
such as external HDD, external SSD, or thumb drive.

Removable Media
= inserted media where the media/session/content identity is durable,
not the reader device. Examples include CD, DVD, Blu-ray, or similar inserted media.
If SD/camera cards are evaluated, determine whether Windows evidence makes them behave more like External Device or Removable Media.

NAS
= networked storage/share, such as a Synology SMB share or other network share.

Cloud
= provider-backed source. iCloud exists now; OneDrive, Google Drive, Dropbox, or others may come later.
```

### Endpoint / Profile / Provenance Model

Use this conceptual model:

```text
Durable Source Endpoint
= source type + durable identity evidence + immutable alias + observed path history

Source ID / Source Profile
= durable endpoint + selected root/folder + intake settings + lifecycle state

Observed Path
= current access path used at setup or run time
= not durable identity

Provenance
= source/path/run based, with future durable endpoint linkage added additively
```

### Non-Cloud Intake

For v1, Local / External Device / Removable Media / NAS intake should remain:

```text
Check Readiness
Run Intake
Show Result
```

Do not introduce mandatory iCloud-style Prepare / Import for non-cloud sources.

### Cloud Boundary

Cloud may remain source-specific because of provider, download, staging, retry, resume, deferred, and cleanup complexity.

Do not change iCloud behavior in this milestone.
