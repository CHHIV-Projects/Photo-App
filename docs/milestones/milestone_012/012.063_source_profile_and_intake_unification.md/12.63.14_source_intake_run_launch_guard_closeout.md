# 12.63.14 Source Intake Run Launch Guard Closeout

## 1. Scope Completed

Implemented a Source Profile readiness launch guard for operator-initiated generic Source Intake.

The Ingestion page now checks Source Profile readiness when the operator clicks generic `Run Intake`. The backend also repeats the readiness check immediately before creating a generic Source Intake run row or starting background intake work.

Implemented launch behavior:

```text
ready:
  allow launch without acknowledgment

path_only:
  require one per-run acknowledgment before launch

needs_review:
  require one per-run acknowledgment before launch

blocked:
  reject launch

provider_specific:
  reject generic Source Intake launch and direct operator to iCloud/provider workflow

unknown:
  reject launch and prompt readiness retry/review
```

## 3. Backend Guard Summary

Added request field:

```text
readiness_acknowledged: bool = False
```

The generic Source Intake launch helper now:

```text
checks for an active Source Intake run
loads the requested Source Profile
runs SourceProfileReadinessService.check_readiness(source_id)
applies launch policy before path checks, Drop Zone checks, run-row creation, or thread start
continues to the existing path and Drop Zone checks only if readiness allows launch
```

Rejected readiness raises `SourceIntakeReadinessBlockedError`. The admin API converts that to a structured `409 CONFLICT` response with safe fields:

```text
error_code
readiness_status
identity_match_status
operator_message
recommended_next_action
warnings
blockers
requires_operator_acknowledgment
hard_block
current Source Intake status
```

Advanced probe internals are not included in launch rejection payloads.

## 4. Frontend Run Intake Flow Summary

Generic row `Run Intake` now calls:

```text
checkSourceProfileReadiness(sourceId)
```

before opening the confirmation modal.

Frontend behavior:

```text
ready:
  opens existing confirmation modal with readiness result

path_only:
  opens confirmation modal with warning and acknowledgment checkbox

needs_review:
  opens confirmation modal with warning and acknowledgment checkbox

blocked:
  shows readiness block message and does not open confirmation

provider_specific:
  shows provider-specific message and does not open confirmation

unknown:
  shows retry/review message and does not open confirmation
```

If the Source Profile details drawer is open for the same source, the run-click readiness result also updates the drawer readiness section.

## 5. Acknowledgment Behavior

The confirmation modal shows one checkbox only when readiness requires acknowledgment:

```text
I reviewed this readiness warning and want to run Source Intake for this source now.
```

The final `Run Intake` button remains disabled until the checkbox is checked.

The acknowledgment is sent only for the current request:

```text
readiness_acknowledged: true
```

It is reset when the modal closes or a new run candidate is selected. No persistent bypass is stored.

## 6. Blocked / Provider-Specific Behavior

Blocked readiness does not open the confirmation modal and does not call the Source Intake launch endpoint.

Provider-specific/cloud/iCloud Source Profiles are blocked from the generic launch endpoint. The UI and backend direct the operator to iCloud Intake/provider-specific workflow.

The older guided generic iCloud Source Intake handoff is now treated as retired/blocked. Its detail-drawer button is disabled with this operator message:

```text
Legacy guided Source Intake handoff is retired. Use the iCloud Intake workflow for this source.
```

The newer unified iCloud Intake workflow is unchanged.

## 7. Existing Guardrails Preservation

Existing generic Source Intake launch checks remain in place after readiness allows launch:


The new readiness guard is additive defense-in-depth.

## 8. Non-Mutation Confirmation

Automated tests assert rejected launch creates no:

```text

observed path rows

```

The guard itself does not write Vault files, asset records, provenance records, cleanup records, or source files.

## 9. iCloud Isolation

Confirmed the true iCloud Intake chunked handoff does not call the generic `start_source_intake` helper or `/api/admin/source-intake/run`.

The unified/chunked iCloud Intake path continues to use:

```text
run_batch_source_intake
intake_mode = icloud_acquisition_batch
```

That path was not guarded or redesigned in this milestone.

The legacy/guided generic iCloud Source Intake handoff is now blocked in favor of the newer iCloud Intake workflow.

```text

Path-only remains allowed for now with per-run acknowledgment.

```

If backend readiness changes between modal open and final start, the modal now shows the backend rejection message and details. The operator can close and retry the readiness-aware run flow.
