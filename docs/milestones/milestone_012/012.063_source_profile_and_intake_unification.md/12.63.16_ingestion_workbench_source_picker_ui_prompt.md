## Goal

Add the first implementation step for the simplified Ingestion Workbench UI.

This milestone should introduce a new source-focused selection surface at the top of the Ingestion page:

```text
Create Source Profile
Source Type selector
Source selector/search
Refresh
Advanced toggle for inactive/test/legacy sources
Selected source summary
```

This milestone should **not** rebuild the selected-source workflow yet.

This milestone should **not** move the long registry table yet.

This milestone should **not** change backend behavior.

The purpose is to let the operator start from:

```text
1. Pick source type.
2. Pick source.
3. See a simple selected-source summary.
```

The selected-source workflow panel comes in the next milestone.

---

## Background / Context

Milestone `12.63.15` completed the Ingestion UI simplification recon.

The approved future design is:

```text
Ingestion Workbench

Top controls:
  Create Source Profile
  Source Type selector
  Source selector/search
  Refresh

Main panel:
  one selected source workflow

Secondary:
  Advanced / Manage Sources
```

The current Ingestion page is functional but cluttered. It includes the iCloud Intake panel, generic Source Profile registry, generic Run Intake controls, readiness UI, source identity UI, iCloud details, legacy/remnant iCloud generic handoff, audit counters, reports, and large drawers.

This milestone adds the source picker/workbench shell while preserving the current page below it during transition.

## Product Direction

The Ingestion page should become a source-focused workbench.

Target mental model:

```text
Pick source type.
Pick source.
Work on that source.
```

This milestone implements only the first two steps and a lightweight selected-source summary.

Future milestones will add:

```text
12.63.17 selected-source workflow panel
12.63.18 combined advanced registry and legacy iCloud cleanup
```

## Product Decisions Locked for This Milestone

### 1. Ingestion Tab Only

Scope is the Ingestion tab only.

Do not redesign or clean up the legacy Admin tab.

Shared backend APIs may be reused, but do not refactor Admin UI.

### 2. No Backend Behavior Changes

Do not change:

```text
Source Intake behavior
iCloud Intake behavior
readiness behavior
endpoint enrollment behavior
cleanup behavior
provenance behavior
Vault behavior
source profile schema
source type persistence
```

### 3. Keep Existing Registry During Transition

Do not remove the existing source registry/table yet.

Do not move it to Advanced / Manage Sources yet.

The old table can remain below the new workbench shell for now.

### 4. Add Workbench Shell at Top

Add a new section near the top of the Ingestion page, below the page header/intro area and above the existing operational panels/table.

Suggested title:

```text
Ingestion Workbench
```

Suggested subtitle:

```text
Choose a source type and source to work with. Source-specific actions will move here as the workflow is simplified.
```

### 5. Source Type Selector

Add operator-facing source type categories:

```text
Local
External
NAS
iCloud
Advanced / Legacy
```

Also include Removable in the design code path only if it is easy and safe, but it may be hidden or disabled until backend support exists.

Recommended visible options for this milestone:

```text
Local
External
NAS
iCloud
Advanced / Legacy
```

Do not persist these categories.

They are presentation categories derived from existing Source Profile data.

### 6. Source Type Mapping

Use frontend presentation mapping from current profile fields.

Recommended mapping:

```text
local_folder + non-UNC root path -> Local
local_folder + UNC root path -> NAS
external_drive -> External
cloud_export + iCloud/cloud_provider=icloud/acquisition_method=icloudpd -> iCloud
scan_batch -> Advanced / Legacy
other -> Advanced / Legacy
unknown/unmapped -> Advanced / Legacy
```

Do not migrate database values.

Do not change backend source type enums.

### 7. Source Selector Defaults to Active Sources

Main selector should default to active/runnable sources only.

Inactive, archived, test, deprecated, and legacy sources should be hidden from the default source selector unless the operator turns on an advanced toggle.

Suggested toggle:

```text
Show inactive / legacy sources
```

The exact label can follow project UI style.

### 8. Source Selector Search

Add search/filter for the source selector.

Search should match:

```text
source label
root path / path hint
cloud provider or account hint where safely available
```

Do not expose secrets.

Masked account username is acceptable if already displayed safely elsewhere.

### 9. Selected Source Summary

When a source is selected, show a simple summary card.

This is not the full workflow panel yet.

Suggested fields:

```text
Source label
Operator-facing source type
Profile status
Short path/provider hint
Cloud provider, when applicable
Managed staging path, when applicable
Endpoint/enrollment status, when available
Latest readiness status, if already checked in current UI state
Primary next area placeholder
```

Suggested placeholder copy:

For filesystem sources:

```text
Filesystem workflow actions will move here next: Check Readiness and Run Intake.
```

For iCloud:

```text
iCloud workflow actions will move here next: Refresh / Prepare and Import / Resume.
```

### 10. Selection Should Connect to Existing Details

Provide a low-risk connection between selected source and existing UI.

Approved options:

```text
Option A: selected source summary includes Details and Manage buttons reusing existing handlers.
Option B: selecting a source visually highlights or scrolls to the matching registry row.
Option C: both, if simple.
```

Preferred:

```text
Details and Manage buttons in the selected-source summary reuse existing drawer handlers.
```

Do not duplicate drawer logic.

Do not create a second details drawer.

### 11. Existing iCloud Intake Panel Remains

Do not move or redesign the existing iCloud Intake panel yet.

The new selector may select iCloud sources, but the actual iCloud workflow remains in the existing iCloud Intake panel during this transition.

The selected-source summary may include copy that iCloud actions remain below for now.

### 12. Existing Run Intake Behavior Remains

Do not change Run Intake behavior.

Do not change readiness preflight or launch guard.

Do not move Run Intake buttons yet.

That belongs to `12.63.17`.

## UI Requirements

### Workbench Placement

Place the new Workbench section near the top of the Ingestion page.

Preferred placement:

```text
After page header / top action area
Before the current iCloud Intake panel and source registry content
```

Do not remove existing sections.

### Workbench Layout

Suggested layout:

```text
Ingestion Workbench

[Create Source Profile] [Refresh]

Source Type:
[Local] [External] [NAS] [iCloud] [Advanced / Legacy]

Source:
[search/select source...]

[ ] Show inactive / legacy sources

Selected Source:
  <summary card>
```

Use existing project styling conventions.

Do not introduce a new UI framework.

### Source Type Controls

Use a UI control consistent with current style:

```text
segmented buttons
tabs
or a dropdown
```

Prefer segmented buttons/tabs if simple, because there are few categories.

Do not over-engineer.

### Source Selector

The selector can be:

```text
dropdown plus search input
filtered list
compact selectable cards
```

Choose the lowest-risk option that fits existing code.

Required behavior:

```text
filter by selected source type
filter by text search
default active sources only
include inactive/legacy when toggle is enabled
show useful empty state
preserve selected source when possible after refresh
```

### Empty States

When no source matches:

```text
No active Local sources found.
Create a Source Profile or show inactive / legacy sources.
```

Adjust category name dynamically.

### Selected Source Summary

Show selected source details without overwhelming the operator.

Suggested summary:

```text
<Source Label>
Type: Local / External / NAS / iCloud / Advanced
Status: active/inactive/archived/etc.
Path / Provider: <short safe hint>
Identity: Enrolled / Not enrolled / Provider-specific / Unknown
Workflow: Filesystem Source Intake / iCloud Intake / Advanced legacy
```

Buttons:

```text
Details
Manage
```

Optional button:

```text
Check Readiness
```

Only include Check Readiness here if it reuses existing readiness logic safely and does not expand scope. It is acceptable to defer Check Readiness to `12.63.17`.

### Advanced / Legacy Category

Advanced / Legacy should include:

```text
scan_batch
other
unmapped source types
non-iCloud cloud_export providers
inactive/test/legacy when toggle is enabled, depending implementation simplicity
```

Do not pretend these are normal active workflows.

Suggested copy:

```text
These sources are retained for history, diagnostics, or unsupported workflows.
```
