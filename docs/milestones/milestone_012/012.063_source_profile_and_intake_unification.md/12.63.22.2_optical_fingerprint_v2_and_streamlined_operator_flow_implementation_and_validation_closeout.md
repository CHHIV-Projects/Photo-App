# 12.63.22.2 Optical Fingerprint v2 and Streamlined Operator Flow — Closeout

## Summary

Milestone 12.63.22.2 implemented the Optical media fingerprint v2 identity format and streamlined the normal Optical operator flow from disc recognition to selected-source Source Intake.

The milestone remained within the approved architecture:

- no Optical-specific ingestion engine was introduced;
- no ripping, conversion, decryption, cloud deletion, Vault semantic change, or provenance semantic change was introduced;
- Optical continues to reuse Source Endpoint / Source Profile identity, Source Selection, selected-source dispatch, the runtime-root bridge, and existing filesystem Source Intake.

## Implementation

Implemented `optical_media_fingerprint_v2` as the current Optical identity format.

Key v2 behavior:

- metadata-only deterministic fingerprint;
- excludes volatile free-space / used-size values;
- excludes file and directory timestamps;
- retains stable disc metadata and manifest shape;
- remains exact-match and fail-closed for launch authorization.

Existing v1 Optical Sources are preserved but treated as legacy. They receive recreate guidance rather than being silently migrated or accepted as current-format launch evidence.

## Optical UI tuning added during operator validation

Post-implementation operator validation exposed several low-effort UI polish needs. These were corrected before closeout:

- For a known Optical disc, `Use This Disc` now reuses/selects the existing Source instead of showing the older `Use Existing Name` review path.
- A known-disc confirmation tile was added so the operator can see that the disc is already known.
- The tile displays the existing device name, existing Source name, entered friendly name, durable identity status, identifier, and observed path.
- The tile persists briefly after Source Selection succeeds so the operator can confirm that the Source Selector and Step 3 have updated.
- After the tile clears, Create Source controls are reset to an unlocked idle state.
- If the operator enters a different friendly name for an already-known disc, the existing device/source are reused and the entered name is not silently applied.
- For known or newly created Optical discs, Step 2 / Source Selector is explicitly populated with the recognized endpoint/device and Source. Step 2 is not hidden; it remains visible as the existing safety gate while Step 3 becomes available.

This was intentionally the low-effort solution. Hiding Step 2 conditionally was not implemented because it would require broader layout/state branching and was not necessary for the validated workflow.

## Operator validation

Operator validation confirmed the current-format Optical flow in the running application:

- A current-format Optical Source was created through the streamlined Optical create flow.
- The Source used an `optical_media_fingerprint_v2` endpoint identity.
- The same mounted disc was recognized repeatedly.
- After clean eject/reinsert, the same disc was recognized as an existing Optical Source rather than a new disc.
- Known-disc behavior now routes directly to selected-source Step 3 while keeping Source Selector populated for visibility.

The operator also ran a live Optical Source Intake after the Source was selected. This was operator-initiated, not Codex-initiated.

Observed live intake facts supplied during validation:

- Source: `Entire disc` (`optical_media`)
- Intake completed.
- Scanned: 2
- Selected for session: 2
- Processed new unique: 0
- Exact duplicates: 2
- Failed/rejected: 1
- Report path shown in UI: `storage/logs/source_intake_reports/source_intake_184.json`

The failed/rejected item was consistent with a non-photo system file on the optical media rather than an Optical identity or dispatch failure.

## Limitations and remaining notes

- Existing v1 Optical Sources remain legacy and require recreation to use v2.
- No v1-to-v2 migration or backfill was implemented.
- Optical Source Intake still uses the existing filesystem Source Intake path.
- Non-photo/system files on optical media can still be rejected by existing Source Intake validation.
- Conditional hiding of Step 2 was not implemented; Step 2 remains visible and populated as the safety/confirmation surface.

## Acceptance conclusion

12.63.22.2 is accepted as a current-format Optical v2 identity and streamlined operator-flow implementation.

The validated path supports:

- new v2 Optical Source creation;
- known-disc recognition;
- clean eject/reinsert recognition;
- automatic selected-source handoff to Step 3;
- visible Source Selector population for known/current Optical Sources;
- existing filesystem Source Intake reuse.

No broader Optical ingestion engine, metadata model, Vault change, provenance change, or cloud deletion behavior was introduced.
