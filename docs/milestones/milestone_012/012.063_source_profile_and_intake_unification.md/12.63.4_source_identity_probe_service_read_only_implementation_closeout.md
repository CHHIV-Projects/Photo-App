## 3. Service/API Summary

Implemented `SourceIdentityProbeService`.

Responsibilities:

- Selects provider based on request/runtime OS.
- Uses `windows_non_admin_probe_v1` for Windows.
- Returns unsupported provider responses for Linux/macOS/unsupported provider names.
- Returns normalized read-only probe responses.

Implemented schemas:

- `SourceIdentityProbeRequest`
- `SourceIdentityProbeResponse`
- `SourceIdentityCapabilitiesResponse`
- `SourceIdentityEvidenceItem`
- `SourceRootCandidate`
- `AccessNodeSummary`
- `SourceIdentityProviderCapabilities`

Implemented provider abstraction:

- `CommandResult`
- `CommandRunner`
- `SourceIdentityProbeProvider` protocol

Implemented Windows provider:

- `WindowsSourceIdentityProbeProvider`
- `WindowsCommandRunner`
- `PathProbeStatus`

Implemented admin endpoints:

- `POST /api/admin/source-identity/probe`
- `GET /api/admin/source-identity/capabilities`

The endpoints are read-only and do not depend on a DB session.

## 4. Behavior Summary by Source Type

`local`:

- Classifies drive roots as `local_volume_root`.
- Classifies folders below drive roots as `local_folder`.
- Uses host, path, and volume evidence.
- Marks local path-only probes as not compared / not applicable for run safety because this milestone does not launch anything.

`external_device`:

- Classifies drive roots as `external_volume_root`.
- Classifies folders below drive roots as `external_folder`.
- Uses path, volume, and PnP/device evidence where available.
- Returns `needs_review` when evidence is partial or medium-confidence.

`removable_media`:

- Classifies roots as `removable_media_root`.
- Classifies folders as `removable_media_folder`.
- Uses path, volume, and PnP/device evidence as supporting evidence.
- Returns `needs_review` when identity evidence is weak/partial.

`nas`:

- Classifies `\\server` as `nas_server_only`.
- Classifies `\\server\share` as `nas_share_root`.
- Classifies `\\server\share\folder` as `nas_share_folder`.
- Blocks server-only paths with `nas_server_not_runnable`.
- Uses exact requested path checks and `net use` mapping summary.
- Does not enumerate unrelated NAS shares.

`cloud`:

- Returns `cloud_provider_not_probeable`.
- Does not probe credentials, cookies, sessions, helper state, or cloud provider auth.
- Points callers to provider-specific readiness.

## 5. Windows Provider Summary

Implemented read-only evidence methods:

- Python filesystem path existence/readability checks.
- Runtime/access-node host summary with masking.
- Bounded subprocess runner with `shell=False`.
- `cmd /c vol <drive>`
- `cmd /c mountvol <drive> /L`
- `cmd /c fsutil fsinfo drivetype <drive>`
- `cmd /c fsutil fsinfo volumeinfo <drive>`
- `pnputil /enum-devices /connected /class DiskDrive`
- `pnputil /enum-devices /connected /class Volume`
- `pnputil /enum-devices /connected /class WPD`
- `pnputil /enum-devices /connected /class USB`
- `net use`

Implemented graceful handling for:

- command success
- command access denied
- command unavailable
- command timeout
- non-zero command exit
- path not found
- path not readable
- access denied
- unsupported OS/provider

Limitations:

- Drive-letter-to-device joins remain partial.
- `Get-Volume`, `Get-Disk`, `Get-Partition`, `Get-CimInstance`, `Get-PnpDevice`, `Get-SmbMapping`, and `wmic path` are not required or used.
- NAS mapped-drive-to-UNC evidence is summarized from `net use`; endpoint persistence and canonical share matching are not implemented yet.
- No Linux or macOS provider is implemented.

## 6. Privacy / Redaction Summary

The implementation suppresses raw command output.

Masked/summarized:

- Host fingerprint.
- Volume serial.
- Volume GUID.
- PnP evidence.
- Common Windows username path segment in evidence.
- Network mapping presence without raw `net use` output.

Explicitly not collected/returned:

- NAS passwords.
- Credential-store secrets.
- Apple credentials.
- Tokens.
- Session cookies.
- 2FA codes.
- Cloud provider secrets.
- Full raw command dumps.

`include_raw_evidence=true` is accepted by the schema but still does not return unsafe raw dumps in this v1 implementation.

## 10. Risks / Known Limitations

- Windows-only provider.
- No Linux mini-server provider yet.
- No macOS provider yet.
- Drive-letter-to-device joins are partial.
- PnP evidence is summarized and not yet deterministically joined to the selected drive.
- Non-admin command availability may vary by Windows environment.
- NAS share/root identity still requires exact path probing and future endpoint persistence.
- Mapped NAS drive canonicalization is not complete beyond `net use` evidence summary.
- Removable media identity remains weak/medium without stronger media/session identifiers.
- No endpoint persistence exists yet.
- No readiness integration exists yet.
- No Source Intake run-launch verification exists yet.
- The API is backend-only; no UI consumes it yet.
