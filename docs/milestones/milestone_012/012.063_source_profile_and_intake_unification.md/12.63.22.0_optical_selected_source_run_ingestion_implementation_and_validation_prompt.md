- a new report format;

## 5.2 Optical media identity

For Optical Sources, the inserted media is the durable identity.

The drive letter or physical Optical drive is not the Source identity.

The existing fingerprint remains authoritative:

```
optical_media_fingerprint_v1
```

Do not change the fingerprint algorithm in this milestone unless current implementation contains a concrete correctness defect that blocks safe launch.

Do not replace the fingerprint with:

- drive letter;
- volume label alone;
- file count alone;
- timestamp alone;
- physical drive identity;
- weak partial media sampling.

## 5.3 Supported media boundary

This milestone applies to filesystem-readable Optical data media containing supported files.

Examples may include:

- CD-ROM data discs;
- DVD-ROM data discs;
- other supported read-only filesystem media already recognized by the existing Optical provider.

Do not add support for:

- audio CD track ripping;
- video DVD decryption or ripping;
- Blu-ray decryption;
- encrypted or copy-protected media;
- unsupported filesystem formats;
- disc writing or burning;
- disc formatting;
- automatic eject.

Unsupported media must remain blocked with a clear message.

# 8. Optical Identity Contract

A valid Optical Source represents one logical Optical medium.

The current inserted medium must match the Source Endpoint’s stored durable fingerprint.

Required identity sequence:

1. identify the currently available Optical drive/path;
2. confirm a supported filesystem-readable disc is inserted;
3. produce the complete existing Optical media fingerprint;
4. compare the current fingerprint to the linked Source Endpoint fingerprint;
5. confirm an exact match;
6. resolve the current disc root;
7. confirm the Source Profile’s endpoint-relative root remains within that disc;
8. allow Step 3 only after all checks pass.

Do not treat any of the following as sufficient identity proof:

- same drive letter;
- same physical drive;
- same volume label;
- same file count;
- same approximate size;
- same Source Profile ID;
- same previously observed path.

---

# 9. Optical Source Root

For a whole-disc Source, the expected Source Profile root may be:

```
endpoint_relative_root = ""
```

For an approved folder within a disc, a non-empty endpoint-relative root may be used if the current Source Creation contract supports it.

The resolved runtime root must:

- be derived by the backend;
- correspond to the currently inserted matched disc;
- be readable;
- remain inside the Optical media root;
- apply the stored endpoint-relative root safely;
- reject traversal outside the media boundary.

Reject:

- missing media;
- changed media;
- incomplete fingerprint;
- fingerprint mismatch;
- unreadable media;
- malformed runtime root;
- path traversal;
- missing subfolder;
- stale selection;
- inactive Source Profile;
- inactive or missing endpoint.

Do not rewrite `source_root_path` merely to run.

Do not create observed-path records merely to run.

# 10. Runtime Revalidation

Immediately before Optical Source Intake launch, the backend must:

1. load the Source Profile;
2. confirm it is active;
3. load the linked Source Endpoint;
4. confirm it is active;
5. confirm its Source Type is Optical;
6. rerun authoritative Source Selection or the shared resolver;
7. confirm:
   - `result=selected`;
   - `availability=available`;
   - `workflow_kind=filesystem_source_intake`;
   - current media identity matched;
8. confirm the current fingerprint is complete;
9. confirm the current fingerprint exactly matches the stored endpoint identity;
10. resolve the current Optical runtime root;
11. apply the endpoint-relative root;
12. confirm the final Source Root is readable;
13. compare the optional selection fingerprint;
14. apply existing operation guardrails;
15. launch existing Source Intake through the runtime-root bridge.

Do not trust frontend-supplied:

- drive letter;
- Source Root;
- workflow kind;
- endpoint ID;
- media fingerprint;
- volume label;
- readiness;
- media identity.

# 12. Readiness Behavior

A current-format Optical Source should be runnable when:

- a supported data disc is inserted;
- the media root is readable;
- the Source Profile is active;
- the linked endpoint is active;
- the endpoint type is Optical;
- the complete current fingerprint is available;
- the fingerprint exactly matches;
- the endpoint-relative root resolves safely;
- no operation conflict exists.

The Source must be blocked when:

- no disc is inserted;
- the drive is unavailable;
- the disc is unreadable;
- the disc filesystem is unsupported;
- fingerprint generation fails or is incomplete;
- a different disc is inserted;
- the Source Profile or endpoint is inactive;
- the configured subfolder is missing;
- selection is stale;
- another ingestion operation conflicts.

Do not require a routine acknowledgment for a fully matched current-format Optical Source.

Do not weaken identity verification to reduce fingerprint time.
