## 3. Product Model Summary

`Endpoint Identity` is durable identity for the storage boundary. Examples are a Windows Volume GUID for Local/External and `\\server\share` for NAS. It is independent of a drive letter and independent of the selected folder depth.

`Source Root` is the exact folder the operator chose for future scanning. It may be the endpoint root or any deeper folder. For NAS it is persisted as canonical UNC. For Local/External it is an absolute Windows drive path.

`Source` is the named Source Profile that combines operator meaning, the exact runtime root, lifecycle status, and an optional durable endpoint link.

Transitional persistence remains:

- Local and NAS profiles persist as `local_folder`.
- NAS is distinguished by UNC root and, once enrolled, `endpoint_source_type=nas`.
- External persists as `external_drive` and uses endpoint type `external_device`.

`SourceProfileSummary` and `SourceProfileDetail` now include nullable `endpoint_source_type`, allowing already-enrolled NAS sources to retain correct operator vocabulary even when the persisted profile type is `local_folder`.

## 6. NAS Behavior

NAS is separate from Local in normal UI.

Direct UNC behavior:

- `\\server\share\folder` is accepted as the exact Source Root.
- Durable identity is based on lower-cased `\\server\share`.
- Folder depth below the share does not change the endpoint fingerprint.
- A server-only path remains blocked as a non-runnable Source Root.

Mapped-drive behavior:

- `WNetGetUniversalNameW` performs narrow, read-only resolution of an existing drive mapping.
- No mapping is created, changed, mounted, or disconnected.
- When resolution succeeds, the canonical UNC folder becomes the persisted Source Profile root and fingerprint input.
- The original mapped path remains the probe observed path and is written as `SourceEndpointObservedPath` evidence on confirmation.
- A mapped network path submitted as Local/External is blocked before profile creation and directs the operator to NAS.
- If a NAS mapped drive cannot resolve, creation stops before profile creation and asks for UNC input.

Exactly one strong verified existing endpoint match is selected and linked automatically when there are no identity blockers. The Create Source click is sufficient confirmation. Multiple matches, non-verified identity, and blockers remain review cases.

## 7. Local / External / Removable / iCloud Behavior

Local:

- Normal label is `Local`.
- UNC input redirects the operator to NAS.
- Normal UI requires an absolute drive path such as `C:\Photos`.
- A readable root plus mountvol Volume GUID can show Verified.
- Drive letter is observed access, not durable identity.

External:

- Normal label is `External`.
- Persisted profile type is `external_drive`.
- A readable root plus mountvol Volume GUID can show Verified.
- A pre-create mapped-network check prevents a mapped NAS drive from being recorded as External.

Removable:

- Visible in Create Source and Source Selector as coming later.
- Disabled in both controls.
- A defensive submit guard also rejects it if UI state is manipulated.

iCloud:

- Normal label is `iCloud`.
- Identity remains provider-specific.
- Generic endpoint enrollment is unavailable.
- Operators remain routed to iCloud Intake.
- No iCloud Intake behavior changed.

## 8. Source Name / Endpoint Alias Handling

`Source Name` is the only normal required name. The UI can suggest a name from endpoint/root context, and the operator may override it.

Endpoint Alias defaults internally from Source Name. It is available only under Advanced Details for new-endpoint review. Existing endpoint aliases remain immutable and are not required confirmation input when linking an existing endpoint.

Endpoint ID is not shown as a normal creation concept. It remains in advanced/debug details and API data.

## 9. Durable Identifier Display

When identity is Verified, the normal result explicitly displays:

- Identifier Type, such as `Volume GUID` or `NAS server/share`.
- Safe masked Identifier, such as `{...846f}` or `\\henderson-nas\photos`.
- The exact Source Root separately.

The UI does not represent endpoint ID alone as durable verification.

## 10. Existing Endpoint Match Wording

The normal plan no longer emphasizes `Duplicate Match`.

- NAS uses `Existing NAS share endpoint found` and `Existing NAS Share`.
- Local/External use `Existing durable source identity found` and `Existing Durable Identity`.
- Endpoint options show alias and match strength; numeric endpoint IDs stay in Advanced Details.

Live validation confirmed that the existing NAS share is expected reusable identity for another folder/source. After the fingerprint fix, the one strong NAS match linked automatically without another warning checkbox or separate confirm action.

## 11. Provenance Audit

No provenance code or data was changed.

Current `Provenance` fields preserve:

- `source_path`
- `source_root_path`
- `source_relative_path`
- `ingestion_source_id`
- `ingestion_run_id`
- `source_label`
- `source_type`
- asset hash, source hash, ingestion timestamp, and optional notes

Source Review displays the full observed source path, source root, relative path, ingestion source ID, and ingestion run ID.

Answers:

- Observed path is stored directly in `provenance.source_path`.
- Source Profile is linked directly by nullable `ingestion_source_id`.
- Endpoint ID is not stored directly in Provenance.
- Current endpoint is indirectly derivable through `ingestion_source_id -> ingestion_sources.endpoint_id` while that mutable link still exists.
- That indirect relation is not an immutable ingestion-time endpoint identity snapshot.
- Original drive-letter/UNC file context is preserved in source path/root/relative fields. For a mapped NAS source, the configured runtime Source Root is canonical UNC; the original mapped input is additionally retained in endpoint observed-path evidence.

Recommended later improvement: snapshot endpoint stable UUID/ID plus fingerprint version/hash at ingestion time while continuing to preserve the original observed source path. This should be additive and must not replace path provenance.

## 16. Risks / Known Limitations

- Mapped-drive live validation was unavailable because no mapped NAS drive was present. Automated provider coverage uses an injected resolver.
- Mapped-drive resolution depends on the current Windows runtime being able to resolve an already-existing mapping.
- NAS remains transitional in persistence: Source Profile type is `local_folder`; endpoint type and canonical UNC distinguish it.
- Local/External normal creation currently expects Windows absolute drive paths. Broader OS support is deferred.
- New endpoint creation can still require explicit review/confirm when identity is not verified, warnings require review, evidence is ambiguous, or blockers exist.
- Read-only Windows commands can time out or return access warnings even when mountvol evidence is sufficient for Verified identity.
- Endpoint identity is not an immutable ingestion-time Provenance snapshot.
- Test endpoint ID `5` remains active while its test Source Profile is inactive; deletion/cleanup was not authorized.
- Source ID `80` remains as an inactive validation artifact; deletion was not authorized.
