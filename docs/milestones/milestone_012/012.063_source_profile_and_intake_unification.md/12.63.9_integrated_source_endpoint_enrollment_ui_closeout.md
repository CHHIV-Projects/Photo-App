# Milestone 12.63.9 - Integrated Source Endpoint Enrollment UI Closeout

## 1. Scope Completed

Integrated optional Source Endpoint enrollment into the existing Ingestion page Create Source Profile drawer.

The operator can now create a Source Profile normally, or choose to enroll durable source identity as a guided follow-up inside the same drawer. Enrollment remains explicit and operator-confirmed.

## 3. UI Summary

The Create Source Profile drawer now shows a Source Identity section.

For supported non-cloud profiles, the drawer offers:

```text
Enroll durable source identity after creating this profile
Endpoint Alias
Create Profile and Plan Enrollment
Enrollment Plan review
Confirm Enrollment
```

The workflow creates the Source Profile first, then calls the enrollment plan endpoint, displays the plan result, and only calls confirm after explicit operator action.

## 4. Existing Profile Enrollment Summary

Existing profile enrollment action was deferred beyond basic visibility.

The Source Profile Details drawer now shows durable identity status from `endpoint_id`:

```text
Enrolled / Not enrolled
Endpoint ID when available
```

No standalone existing-profile enrollment action, endpoint management page, or relink flow was added.

## 5. API Client / Type Summary

Added frontend API functions:

```text
planSourceEndpointEnrollment(...)
confirmSourceEndpointEnrollment(...)
```


## 6. Backend API Change Summary

Added one small additive field:

```text
SourceProfileSummary.endpoint_id: int | None
```

`SourceProfileDetail` inherits this field. No source profile creation semantics changed.

## 7. Source Type Mapping Summary

Implemented conservative mapping:

```text
cloud_export -> generic endpoint enrollment unavailable
external_drive -> probe source_type = external_device
local_folder with non-UNC path -> probe source_type = local
local_folder with UNC path -> probe source_type = nas
scan_batch -> endpoint enrollment unavailable
other -> endpoint enrollment unavailable
```

No new persisted backend Source Profile types were added.

## 8. Create-Only Flow Summary

Create-only behavior remains available.

When enrollment is not selected:

```text
create Source Profile normally
refresh profile list
close drawer
do not call enrollment endpoints
do not run Source Intake
```

## 9. Create + Enroll Flow Summary

When enrollment is selected:

```text
create Source Profile
retain returned source_profile_id
build probe_request from created profile
call /source-endpoints/enrollment/plan
display plan result
require explicit Confirm Enrollment action
call /source-endpoints/enrollment/confirm
display success/error
refresh profile list
```

## 10. Plan UI Behavior

The plan display shows:

```text
plan status
endpoint action
candidate source type
filesystem boundary type
observed path
identity confidence
fingerprint evidence strength
alias and normalized alias
possible endpoint matches
blockers
warnings
required confirmations
advanced plan fingerprint/provider/codes
```

If alias or endpoint selection changes after planning, the UI provides Refresh Plan and disables confirm until the plan is current.

## 11. Confirm UI Behavior

Confirm is disabled when:

```text
plan is missing
plan has blockers
plan is not ready/reviewable
new endpoint alias is empty
alias changed after planning
existing endpoint link requires a selected endpoint
required confirmations are not acknowledged
```

On success, the UI shows endpoint id and observed path id when returned. It also states that Source Intake behavior is unchanged.

## 12. NAS UI Behavior

UNC local-folder paths are mapped to NAS enrollment.

For NAS plans, the UI explains:

```text
NAS endpoint identity is server + share.
The full configured folder remains this Source Profile root.
```

NAS server-only paths rely on backend blockers and are displayed as blocked plans. No NAS credentials, mount UI, or share enumeration was added.

## 13. Cloud/iCloud UI Behavior

Cloud Export / iCloud remains provider-specific.

Generic endpoint enrollment is not offered for `cloud_export`; the UI displays an explanatory note instead. No iCloud behavior changed.

## 14. Admin Page / Legacy Controls

Legacy Admin page controls were not removed, reorganized, or changed.

## 15. Source Intake Isolation

Source Intake behavior was not changed.

Enrollment does not:

```text
run Source Intake
change Source Intake readiness
change run launch behavior
write Vault files
change cleanup behavior
```
