## Goal

Clean up the **Create Source** process so it matches the product model:

```text
Endpoint Identity + Source Root = Source
```

This milestone should make the source creation flow understandable before continuing with the selected-source Ingestion Workbench.

The intended operator flow is:

```text
1. Create Source, if needed.
2. Choose Source.
3. Run Intake/Ingestion using source-appropriate controls.
```

This milestone focuses on step 1:

```text
Create Source
```

Do not implement the selected-source ingestion workbench yet.

## Product Model

Use these definitions consistently.

### Endpoint Identity

The durable device/cloud/share identity behind the source.

Examples:

```text
iCloud:
  provider/account/workflow identity

Local:
  local volume identity

NAS:
  NAS server/share identity

External:
  external volume identity

Removable:
  removable media identity, future/coming later until persisted support exists
```

### Source Root

The folder/scope under the endpoint that should be scanned.

Examples:

```text
C:\Users\chhen\OneDrive\Pictures\Scans

E:\WD Backup.swstor\...

\\HENDERSON-NAS\Photos\Dad Files\DadFilesClean1x\Photos\32. RMH Pic\1. Old RMH
```

The entered path is the current observed/runnable path and may include a drive letter or UNC path.

### Source

A runnable ingestion source.

Product formula:

```text
Source = Endpoint Identity + Source Root + source settings/name
```

Examples:

```text
Endpoint:
  Henderson NAS = \\HENDERSON-NAS\Photos

Source Root:
  Dad Files\DadFilesClean1x\Photos\32. RMH Pic\1. Old RMH

Source:
  Henderson NAS - Dad Files\DadFilesClean1x\Photos\32. RMH Pic\1. Old RMH
```

For usability, the UI may suggest a shorter source name, but the full root-relative path must remain visible in details.

## Product Decisions Locked for This Milestone

### 1. Create Source, Not Create Source Profile

Normal UI should use the phrase:

```text
Create Source
```

not:

```text
Create Source Profile
```

The backend may still use `SourceProfile` internally.

### 2. One Create Source Entry Point

The current UI has Create Source Profile controls in more than one place.

This milestone should move toward one primary Create Source box above the Source Selector.

Preferred layout:

```text
Create Source
Source Selector
Ingestion Workbench
```

Do not leave duplicate normal operator-facing Create Source buttons if they can be safely removed or consolidated.

If a duplicate must remain temporarily for safety, mark it clearly as transitional and document why.

### 3. Create Source as a Box Above Source Selector

Replace the current “weird button only” feel with a real top-level Create Source section.

Recommended behavior:

```text
Collapsed by default:
  Create Source button / compact box

Expanded:
  Source Type
  Source Name
  Location / Root Path
  identity verification result
  Create / Confirm action
```

The exact UI can follow current styling, but the operator should see Create Source as a first-class section.

### 4. Source Type Options Must Match Source Selector

Create Source and Source Selector should use the same user-facing type vocabulary:

```text
Local
NAS
External
Removable
iCloud
Advanced / Legacy
```

Do not show `Local / NAS Folder` as a combined normal choice.

Local and NAS must be separate user-facing choices.

### 5. NAS Is a Separate User-Facing Type

NAS must not be commingled with Local in normal UI.

For the operator:

```text
Local ≠ NAS
```

Even if backend persistence remains transitional, the UI must present NAS separately.

### 6. NAS May Be UNC or Mapped Drive

NAS source creation should support the concept that NAS can be accessed as either:

```text
Direct UNC:
  \\HENDERSON-NAS\Photos\Dad Files\...

Mapped drive:
  Z:\Dad Files\...
```

Product rule:

```text
Mapped drive letter is an observed access path, not durable NAS identity.
```

The durable NAS identity should be server/share when available:

```text
\\HENDERSON-NAS\Photos
```

If a mapped drive path can be safely resolved to UNC/server/share, proceed as NAS.

If it cannot be resolved, do not silently treat it as Local. Show a clear message:

```text
Mapped NAS path detected, but the UNC share could not be resolved. Enter the UNC path instead.
```

### 7. Root Can Be Any Folder Level

For NAS, External, Local, or Removable, the selected root is the exact folder to scan.

It may be high in the hierarchy or deep for testing.

Do not assume the root is only the first folder under the endpoint/share/volume.

### 8. Source Name and Endpoint Alias

Normal UI should ask for one user-facing name:

```text
Source Name
```

Endpoint Alias should not be a second required normal field.

Rules:

```text
Endpoint alias may default from Source Name.
Endpoint alias may remain available in Advanced Details if needed.
Endpoint ID remains advanced/debug only.
```

Future product clarification is still needed, but this milestone should reduce the visible redundancy.

### 9. Identity Result Must Show Actual Identifier

When the system says identity is Verified, the UI must show the actual safe identifier:

```text
Identifier type:
  Volume GUID
  NAS server/share
  Provider workflow

Identifier:
  {...}
  \\henderson-nas\photos
  iCloud
```

Do not make the operator trust only:

```text
Endpoint ID
Verified badge
fingerprint evidence
```

### 10. Removable Is Planned but Not Fully Supported

Removable should be visible as a product concept, but must not be silently mapped to a misleading backend source type.

Allowed behavior:

```text
Removable: Coming later
```

or:

```text
Removable: Disabled until persisted Source Profile support exists
```

Document the reason.

### 11. iCloud Remains Provider-Specific

iCloud Create Source should stay provider-specific.

Do not use generic endpoint identity enrollment for iCloud.

Do not change iCloud Intake behavior.

Add or refactor into a top-level box/section above Source Selector.

```text

[Location / Root Path]
[Create Source / Check Identity]

  Identifier type
  Identifier
  Root path
  Source created / linked status
```

This may reuse the existing drawer internally, but the normal page should present Create Source as a box/section, not only a scattered button.

### 2. Align Source Type Options

Use the same visible choices in Create Source and Source Selector:

```text
Local
NAS
External
Removable
iCloud
Advanced / Legacy
```

Do not show `Local / NAS Folder`.

Backend persistence may remain mapped if necessary, but the UI vocabulary must be separate and documented.

### 3. NAS Path Handling

For NAS creation:

Accept direct UNC paths:

```text
\\server\share\folder
```

For mapped drive paths:

```text
Z:\folder
```

attempt safe resolution to UNC/server/share using existing probe/provider capabilities or Windows non-admin evidence where available.

If resolution succeeds:

```text
Endpoint identity:
  \\server\share

Source root:
  folder relative to share
```

If resolution fails:

```text
Do not create as Local.
Show a clear operator message asking for UNC path.
```

Do not request credentials.

Do not mount NAS.

Do not modify network mappings.

### 4. Local Path Handling

For Local creation:

```text
Local means local filesystem/volume, not UNC/NAS.
```

If operator enters a UNC path while Local is selected, redirect/indicate NAS.

Suggested behavior:

```text
This looks like a NAS path. Use source type NAS.
```

### 5. External Path Handling

For External creation:

```text
External means external volume/drive path.
```

Use the durable identity policy from `12.63.17`:

```text
Volume GUID + readable root -> Verified
```

Drive letter is observed path only.

### 6. Source Name Suggestion

When possible, suggest a source name from endpoint/source root.

Examples:

```text
Henderson NAS - Dad Files
External 1 - WD Backup Photos
Chuck PC - Scans
```

But allow user override.

Do not require a separate endpoint alias field in the normal UI.

### 7. Existing Endpoint Match Wording

When creating a NAS source under an existing NAS share endpoint, do not show scary wording like:

```text
Duplicate Match
```

Preferred wording:

```text
Existing NAS share endpoint found
```

or:

```text
Existing durable source identity found
```

Clarify:

```text
This is expected when multiple sources use different folders under the same NAS share.
```

Apply similar wording for External/Local if multiple sources share the same volume endpoint.

### 8. Provenance Audit

Do a read-only audit of current provenance/source review display.

Question to answer:

```text
When an asset is imported, does provenance only record the observed path,
or does it also link to source_id / endpoint_id / durable identity context?
```

Required output in closeout:

```text
Current provenance fields used
Whether source_id is present
Whether endpoint_id is present or derivable
Whether observed drive-letter/UNC path is preserved
What should be improved later
```

Do not rewrite provenance in this milestone.

Do not migrate old provenance.

Do not change ingestion behavior unless a very small display-only fix is necessary.

### 9. Preserve Existing Safety

Do not change Source Intake execution behavior.

Do not change iCloud Intake behavior.

Do not run any ingestion.
