# 9. NAS Identity Contract

NAS durable endpoint identity is:

```
canonical server + share
```

Examples:

```
\\HENDERSON-NAS\Photos
```

The Source Profile root is relative to that endpoint boundary.

Example:

```
Endpoint:\\HENDERSON-NAS\Photosendpoint_relative_root:Camera importsResolved Source Root:\\HENDERSON-NAS\Photos\Camera imports
```

The server alone is not a valid endpoint boundary:

```
\\HENDERSON-NAS
```

A valid NAS Source requires:

- server;
- share;
- optional endpoint-relative folder;
- linked active endpoint;
- active Source Profile;
- readable resolved UNC Source Root.

---

# 10. Runtime Revalidation

Immediately before NAS Source Intake launch, the backend must:

1. load the current Source Profile;
2. confirm it is active;
3. load the linked Source Endpoint;
4. confirm the endpoint is active;
5. confirm the endpoint Source Type is NAS;
6. re-run Source Selection or the shared authoritative resolver;
7. require:
   - `result=selected`;
   - `availability=available`;
   - `workflow_kind=filesystem_source_intake`;
   - identity matched;
8. resolve the current canonical UNC endpoint path;
9. combine it with `endpoint_relative_root`;
10. confirm the resulting root remains inside the endpoint’s server/share boundary;
11. confirm the resolved Source Root exists and is readable;
12. compare the optional selection fingerprint;
13. apply the existing operation guardrail;
14. launch existing Source Intake using the runtime-root bridge.

Do not trust frontend-supplied:

- UNC path;
- workflow kind;
- endpoint ID;
- server;
- share;
- endpoint-relative root;
- identity;
- readiness status.

---

# 11. NAS Runtime-Root Rules

The runtime root must:

- be derived on the backend;
- be a valid UNC path;
- include a share;
- remain within the selected endpoint’s canonical share boundary;
- use the selected Source Profile’s endpoint-relative root;
- be readable at launch time.

Reject:

- server-only paths;
- malformed UNC paths;
- a different share;
- traversal outside the endpoint share;
- mapped-drive substitutions as authority;
- missing folders;
- inaccessible paths;
- stale selection;
- inactive profiles or endpoints.

Do not persist the runtime root merely because it was used for launch.

Do not update:

- `source_root_path`;
- endpoint identity;
- observed paths;
- aliases;
- endpoint-relative root.

The existing run/report may record the actual runtime root as execution evidence where already supported.

# 13. Readiness Behavior

A valid current-format NAS Source should be runnable when:

- endpoint type is NAS;
- canonical server/share is valid;
- Source Root is readable;
- endpoint identity matches;
- Source Profile is active;
- no operation conflict exists.

A NAS Source must be blocked when:

- the share is unavailable;
- Windows access is denied;
- the folder does not exist;
- the Source Root is outside the share boundary;
- the selected endpoint differs from the current endpoint;
- selection is stale;
- the profile or endpoint is inactive;
- the path is server-only;
- the Source is legacy/unresolved and cannot be safely verified.

Do not require acknowledgment for a normal current-format NAS Source that is fully verified and readable.

Retain conservative handling for unresolved legacy NAS records.
