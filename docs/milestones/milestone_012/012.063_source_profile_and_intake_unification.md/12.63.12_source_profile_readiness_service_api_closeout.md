## 3. Service Summary

Added:

```text
SourceProfileReadinessService
```

The service answers:

```text
Can this runtime safely use this Source Profile now?
```

It:

```text
loads the Source Profile
resolves the effective path
maps Source Profile type to probe source type
returns provider_specific for cloud/iCloud without filesystem probing
blocks inactive/non-runnable generic profiles before probing
calls the read-only Source Identity Probe service for supported filesystem sources
loads the linked Source Endpoint when endpoint_id is present
compares current probe fingerprint to linked endpoint fingerprint
returns a compact operator-facing readiness result
```

It does not run Source Intake or write any runtime records.

## 5. Readiness Status Behavior

Implemented statuses:

```text
ready
path_only
needs_review
blocked
provider_specific
unknown
```

Current behavior:

```text
ready:
  enrolled endpoint strongly matches current probe and probe is safe_to_run=true

path_only:
  endpoint_id is null, path is readable/runnable, Source Intake remains allowed with acknowledgment recommended

needs_review:
  enrolled source is readable, but identity evidence is weak/medium/incomplete or safe_to_run requires review

blocked:
  hard availability, source type, endpoint, or identity safety problem

provider_specific:
  cloud/iCloud source uses provider-specific workflow, not generic filesystem readiness

unknown:
  reserved for unexpected indeterminate states
```

## 6. Identity Match Behavior

Implemented match statuses:

```text
not_enrolled
matched
needs_review
mismatch
unavailable
unsupported
provider_specific
ambiguous
unknown
```

Strong match requires:

```text
same endpoint source_type
same durable identity_fingerprint_hash
endpoint not retired
current path readable and valid as source root
probe safe_to_run=true
current fingerprint strength=strong
```

If a current strong fingerprint differs from the linked endpoint fingerprint, readiness is:

```text
readiness_status = blocked
identity_match_status = mismatch
```

If the source is readable but the current fingerprint is weak, medium, unavailable, or otherwise not strong enough to prove a durable match, readiness is:

```text
readiness_status = needs_review
identity_match_status = needs_review
can_run_source_intake = true
requires_operator_acknowledgment = true
hard_block = false
```

Observed path alone is not treated as durable identity evidence.

## 7. Path-Only Behavior

Path-only profiles remain valid.

For `endpoint_id = null` and a readable/runnable filesystem path:

```text
readiness_status = path_only
identity_match_status = not_enrolled
can_run_source_intake = true
requires_operator_acknowledgment = true
hard_block = false
```

Operator message:

```text
Source can run, but durable source identity enrollment is recommended.
```

For missing/unreadable paths, path-only profiles return blocked/unavailable.

## 8. Enrolled Endpoint Behavior

Implemented behavior:

```text
strong match:
  ready / matched / runnable / no acknowledgment required

weak, medium, or incomplete readable evidence:
  needs_review / runnable / acknowledgment required

strong fingerprint mismatch:
  blocked / mismatch / not runnable

missing, access denied, invalid, unreadable path:
  blocked / unavailable / not runnable

retired endpoint or endpoint source-type mismatch:
  blocked / mismatch / not runnable

linked endpoint missing:
  blocked / mismatch / not runnable
```

## 9. Cloud / iCloud Behavior

Cloud/iCloud remains provider-specific.

For `cloud_export` and direct `cloud` source types:

```text
readiness_status = provider_specific
identity_match_status = provider_specific
can_run_source_intake = false
hard_block = false
```

iCloud message:

```text
iCloud readiness is handled by iCloud Intake.
```

The generic readiness service does not run filesystem probes for cloud/iCloud profiles and does not change iCloud Intake.

## 16. Risks / Known Limitations

Known limitations:

```text
UI is not implemented yet.
Run-launch guard is not implemented yet.
Readiness results can become stale after removable drive/NAS/source state changes.
Path-only profiles remain allowed for now.
needs_review policy is API-only until future UI/run-launch acknowledgment work.
NAS mapped-drive identity may require review if share evidence is incomplete.
The readiness service does not persist observed path evidence.
Cloud/iCloud durable endpoint identity remains separately undesigned.
```

Behavior note:

An enrolled endpoint with no comparable durable fingerprint is not treated as ready. If the source is readable and evidence is non-conflicting, the service returns `needs_review`; if evidence conflicts or is unsafe, it returns `blocked`.
