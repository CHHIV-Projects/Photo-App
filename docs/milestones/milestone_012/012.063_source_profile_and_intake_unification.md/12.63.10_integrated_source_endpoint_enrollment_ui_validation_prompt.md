## Goal

Manually validate the integrated Source Endpoint enrollment UI implemented in `12.63.9`.

This milestone should validate the running browser workflow on the Ingestion page:

```text
Create Source Profile
optional Source Identity enrollment
Plan Enrollment
Review plan result
Confirm Enrollment
Success/error display
```

This is primarily a validation milestone.

Small, targeted bug fixes are allowed **only** when they are necessary to make the intended `12.63.9` UI flow work as designed.

Do not add new features.

Do not start readiness integration.

Do not start Source Intake run-launch verification.

Do not clean up the legacy Admin page.

---

## Background / Context

Milestone `12.63.8` implemented backend-only Source Endpoint enrollment:

```text
POST /api/admin/source-endpoints/enrollment/plan
POST /api/admin/source-endpoints/enrollment/confirm
```

Important `12.63.8` backend behavior:

```text
/plan is read-only.
/confirm re-runs/revalidates the probe and writes only after explicit confirmation.
No persistent enrollment-plan table was added.
No Source Intake launch behavior changed.
No readiness behavior changed.
No provenance behavior changed.
```

Milestone `12.63.9` integrated endpoint enrollment into the existing Ingestion page Create Source Profile drawer.

Important `12.63.9` behavior:

```text
Create-only flow remains available.
Create + enroll flow creates Source Profile first, then calls /plan, then shows plan result, then calls /confirm after explicit operator confirmation.
Cloud Export / iCloud remains provider-specific and does not use generic endpoint enrollment.
Source Intake behavior is unchanged.
Legacy Admin controls were not removed or reorganized.
```

`12.63.9` validation included backend tests, frontend lint, frontend build/type check, and diff checks, but manual browser validation was not performed.

This milestone fills that gap.

## Product Decisions Locked for This Milestone

### 1. Validate Existing Integrated UI

Validate the integrated Create Source Profile drawer flow implemented in `12.63.9`.

Do not replace it with a standalone enrollment page.

### 3. Stop Before Large Changes

Examples of changes that require approval:

```text

```

Do not run Source Intake as part of validation.

Do not click any UI action that starts intake.

Validate that Source Profile creation still works without endpoint enrollment.

Endpoint enrollment must remain optional.

### 6. Cloud/iCloud Remains Provider-Specific

Validate that `Cloud Export / iCloud` still shows the cloud-specific fields and does not use generic filesystem endpoint enrollment.

### 7. Test Data Must Be Clearly Labeled

Examples:

Do not run intake for these profiles.

## Safety Boundaries

Preserve these rules:

```text
Source Intake remains the ingestion authority.
The Vault remains immutable canonical storage.
Original media must not be modified.
Cloud acquisition remains staging-only.
Cleanup may only target verified local cloud/acquisition staging files.
Non-cloud source roots are not disposable staging.
No remote cloud deletion is allowed.
No Vault deletion is allowed.
No DB/provenance deletion is allowed.
Provenance must remain explainable.
Drive letters and transient mount paths are observations, not durable identity.
NAS credentials must not be stored or requested.
Apple credentials, 2FA codes, session cookies, tokens, and secrets must not be stored.
Endpoint enrollment must be explicit and operator-confirmed.
Endpoint alias is immutable for v1.
Legacy path-only profiles must remain valid.
```
