## Goal

Implement the backend Source Profile readiness service and API designed in `12.63.11`.

This milestone adds a **read-only readiness check** for Source Profiles.

The readiness service should answer:

```text
Can this runtime safely use this Source Profile now?
```

It should not run Source Intake.

It should not change Source Intake launch behavior yet.

It should not change iCloud Intake.

It should not write Vault files, source files, cleanup files, asset records, provenance records, or Source Intake run records.

This milestone builds on existing work. It does **not** replace the already-working local/external Source Intake flow.

---

## Product Framing

Local and external Source Intake already worked before this source identity arc.

The purpose of this milestone is not to reinvent that working path.

The purpose is to add a small, reusable readiness layer that combines:

```text
existing Source Profile path verification
existing Source Identity Probe
existing Source Endpoint enrollment data
simple operator-facing readiness states
```

The readiness layer should prepare the system for later UI and run-launch guard milestones.

The operator model should remain simple:

```text
Check Readiness
Run Intake
```

Do not create a long, multi-step readiness wizard.

## Product Decisions Locked for This Milestone

### 1. Backend/API Only

Implement backend service, schemas, endpoint, and tests.

Do not implement frontend UI changes in this milestone.

### 2. Read-Only First

This readiness check should be non-destructive.

It may:

```text
load Source Profile data
resolve effective source path
call the read-only Source Identity Probe service
load linked Source Endpoint data
compare current probe identity to enrolled endpoint identity
return readiness status
```

It must not:

```text
run Source Intake
create Source Intake runs
copy files
write Vault files
write asset records
write provenance records
delete files
modify Source Profiles
modify endpoint enrollment
persist readiness history
persist observed path records
change cleanup behavior
change iCloud behavior
```

### 3. Path-Only Profiles Remain Valid

Profiles with:

```text
endpoint_id = null
```

remain valid.

If the path is readable, readiness should be:

```text
readiness_status = path_only
can_run_source_intake = true
requires_operator_acknowledgment = true
```

The message should recommend durable source identity enrollment but not block current use.

### 4. Enrolled Profiles Use Endpoint Identity Comparison

For profiles with:

```text
endpoint_id != null
```

readiness should compare the current probe identity to the linked endpoint identity.

Strong match should require:

```text
same endpoint source_type
same durable identity_fingerprint_hash
endpoint not retired
current path is readable
current source root boundary is valid
```

Observed path alone is not durable identity evidence.

### 5. Needs Review Is Not a Hard Block

For this API, `needs_review` should mean:

```text
The source is readable, but identity evidence is medium/weak or needs operator confirmation.
```

Return:

```text
can_run_source_intake = true
requires_operator_acknowledgment = true
hard_block = false
```

Future run launch will require explicit per-run acknowledgment.

Do not implement run-launch acknowledgment yet.

### 6. Hard Block True Safety Problems

Hard blockers should include:

```text
endpoint mismatch
unavailable path
access denied
path is not a directory
NAS server-only path
unsupported source type
inactive/non-runnable profile status
unsafe or conflicting identity evidence
```

Return:

```text
can_run_source_intake = false
hard_block = true
```

### 7. iCloud / Cloud Remains Provider-Specific

For iCloud/cloud source profiles, generic readiness should not run filesystem endpoint checks.

Return:

```text
readiness_status = provider_specific
identity_match_status = provider_specific
can_run_source_intake = false
hard_block = false
recommended_next_action = Use iCloud Intake
```

Suggested message:

```text
iCloud readiness is handled by iCloud Intake.
```

Do not change iCloud Intake.

### 8. Keep Operator Model Simple

The response should support simple UI later:

```text
badge
message
recommended next action
advanced details
```

Do not expose a complicated 10-step workflow in the API model.

## API Design

Add endpoint:

```text
POST /api/admin/source-profiles/{source_id}/check-readiness
```

Use `POST` because this performs a live probe and may touch slow/removable/NAS paths.

No request body is required unless existing project conventions require one.

Optional request body may be allowed for future flags, but keep v1 simple.

## Readiness Status Model

Implement these top-level statuses:

```text
ready
path_only
needs_review
blocked
provider_specific
unknown
```

Meanings:

```text
ready:
  Source is reachable and enrolled endpoint identity is acceptable.

path_only:
  No durable endpoint is enrolled, but the path is usable.
  Source Intake remains allowed for now with warning.

needs_review:
  Source is readable, but identity evidence is medium/weak or needs operator confirmation.
  Future Source Intake launch should require per-run acknowledgment.

blocked:
  Hard safety or availability problem.
  Source Intake should not run.

provider_specific:
  Generic readiness does not apply, such as iCloud.
  Use provider-specific workflow.

unknown:
  Readiness could not be determined unexpectedly.
  Operator should retry or inspect details.
```

---

## Identity Match Status Model

Implement these match statuses:

```text
not_enrolled
matched
needs_review
mismatch
unavailable
unsupported
provider_specific
ambiguous
unknown
```

Mappings:

```text
not_enrolled:
  endpoint_id is null

matched:
  current probe strongly matches linked endpoint

needs_review:
  readable source but evidence is medium/weak/incomplete

mismatch:
  linked endpoint exists but current durable fingerprint differs

unavailable:
  source path missing, access denied, not directory, or unreadable

unsupported:
  source type or boundary unsupported

provider_specific:
  cloud/iCloud handled outside generic readiness

ambiguous:
  conflicting evidence or unsafe ambiguity

unknown:
  unexpected indeterminate result
```
