# Milestone 12.63.8 - Source Endpoint Enrollment Service Implementation Closeout

## 1. Scope Completed

Implemented backend-only Source Endpoint enrollment planning and confirmation.

This milestone adds a stateless enrollment flow:

```text
POST /api/admin/source-endpoints/enrollment/plan
POST /api/admin/source-endpoints/enrollment/confirm
```

The flow uses the existing read-only Source Identity Probe service as input. Planning is read-only. Confirmation re-runs the probe, recomputes the plan, checks the reviewed plan fingerprint when provided, and writes only after explicit operator confirmation.

No persistent enrollment-plan table was added.

## API Summary

Added admin-only backend endpoints:

```text
POST /api/admin/source-endpoints/enrollment/plan
POST /api/admin/source-endpoints/enrollment/confirm
```

`/plan` accepts:

```text
source_profile_id
probe_request
proposed_alias optional
selected_existing_endpoint_id optional
operator_review_acknowledged optional
```

`/confirm` accepts:

```text
source_profile_id
probe_request
confirmed_alias optional
selected_existing_endpoint_id optional
plan_fingerprint optional
operator_confirmed
operator_review_acknowledged optional
```

The endpoints are wired through `backend/app/api/admin.py` and use the existing source identity probe service dependency hook, so tests and future callers can supply fake/read-only probe services.

## Plan Behavior Summary

Plan behavior:

```text
/plan = read-only probe + endpoint candidate + match/alias analysis
```

The planning service:

```text
looks up the existing Source Profile
runs a read-only Source Identity Probe
builds a non-persistent endpoint candidate
normalizes and validates alias input
checks strong same-fingerprint endpoint matches
checks alias conflicts
reports blockers, warnings, and required confirmations
returns a plan_fingerprint
```

If the Source Profile does not exist, the response is blocked and no probe is run.

## Confirm Behavior Summary

Confirm behavior:

```text
/confirm = re-probe + recompute/revalidate plan + write only if confirmed
```

The confirmation service:

```text
requires operator_confirmed = true
requires confirmed_alias only when creating a new endpoint
does not require confirmed_alias when linking an existing endpoint
recomputes the plan from the supplied probe_request
checks plan_fingerprint when provided
blocks stale plans
creates/links endpoint records only after the recomputed plan is ready
rolls back on unexpected write failure
```

Idempotent confirm behavior was implemented:

```text
same source profile
same already-linked endpoint
same compatible fresh probe
same observed path
```

returns completed/already-linked and does not create duplicate observed-path rows.

## Source-Type Behavior

Implemented behavior:

```text
local/external_device/removable_media: enrollable when probe is completed, root candidate is valid, and no blocker exists
nas: enrollable at share root or share folder when probe is completed, root candidate is valid, and no blocker exists
cloud: deferred/blocked from generic endpoint enrollment in this milestone
unsupported/unavailable/provider_error/blocked probes: blocked
invalid source-root candidates: blocked
```

Medium or weak evidence can require operator review before confirmation.

## NAS Behavior

NAS endpoint identity uses:

```text
server + share
```

Example:

```text
\\HENDERSON-NAS\Photos\Camera imports
```

creates the endpoint fingerprint from:

```text
HENDERSON-NAS + Photos
```

The full folder remains the Source Profile root and observed path. A NAS server-only path remains blocked because it is reachable context, not a runnable Source Root.

## Privacy / Evidence Storage Summary

The service does not store raw probe results during planning.

The confirm path stores only sanitized operational summaries:

```text
identity_fingerprint_hash
identity_fingerprint_version
identity_confidence
filesystem_boundary_type
source_root_candidate_path
probe status fields
safe blockers/warnings JSON
safe evidence summary JSON
```

It does not store:

```text
credentials
tokens
signed URLs
raw helper payloads
Apple account identifiers
raw serial-number text
raw probe API response snapshots
```

Observed path alone is treated as weak evidence and does not create a strong duplicate endpoint match.

## Risks / Known Limitations

Known limitations:

```text
Medium-confidence duplicate matching is deferred.
Weak/path-only fingerprint fallback can support reviewed creation but cannot create strong duplicate matches.
The plan fingerprint is deterministic for the recomputed candidate and request choices, but no server-side plan record exists.
Idempotent retry allows a plan fingerprint mismatch only when the Source Profile is already linked to the same compatible endpoint.
Cloud enrollment remains explicitly deferred.
Future frontend work must decide how operators review blockers, warnings, required confirmations, and strong matches.
```
