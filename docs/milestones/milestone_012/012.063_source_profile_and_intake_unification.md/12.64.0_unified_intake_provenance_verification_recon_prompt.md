The closeout must provide a step-by-step controlled validation roadmap for the next milestone.

The roadmap should define the exact order of operations.

At minimum, it should cover:

### Baseline

- calculate and record SHA-256 for each prepared filesystem copy;

- confirm the hashes match;

- identify whether the content already exists in the current database or Vault;

- define how to handle the test if the Asset is already known;

- record the newly created Source Profile and Source Endpoint identifiers.

### First Unique Intake

Verify:

```text

Vault-file count
provenance state
Source Profile
Source Endpoint

```

### Same-Source Repeat

Run the same Source again.

Verify:

```text
no second Asset
no second Vault file
no uncontrolled duplicate provenance
correct known/exact-duplicate reporting
existing provenance preserved
```

### Cross-Source Intake

Ingest the same bytes from the remaining filesystem Sources.

After each Source, verify:

```text
one Asset remains
one Vault file remains
new legitimate Source observation exists
earlier Source observations remain
Source-relative path is correct
Source Endpoint/Profile relationship is correct
```

### Optical Identity Safety

Verify:

- the intended disc is recognized;

- repeated intake is deterministic;

- wrong or unavailable disc blocks launch;

- blocked launch creates no Source Intake run, Asset, or provenance.

### iCloud Import

Verify:

- the intended iCloud item or exact bytes can be identified;

- acquired staged-file SHA-256 matches the filesystem test file when testing exact duplicate provenance;

- the iCloud Source observation is preserved;

- no second Asset or Vault file is created when hashes match;

- staging cleanup removes only eligible temporary files;

- cleanup does not remove provenance or history.

If iCloud returns different bytes, classify that result as a different-content test rather than a failed exact-duplicate provenance test.

### Failed or Rejected Item

Recommend one safe, controlled rejected or failed-file test only if it can be performed without introducing cleanup risk.

Verify that unsuccessful processing does not create false successful Asset provenance.
