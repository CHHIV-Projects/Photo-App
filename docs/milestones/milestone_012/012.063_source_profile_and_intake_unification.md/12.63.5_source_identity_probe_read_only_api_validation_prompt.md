## Product Decisions Locked for This Milestone

Do not reopen these.

### 1. Validation Is Read-Only

The validation may call:

```text
SourceIdentityProbeService
POST /api/admin/source-identity/probe
GET /api/admin/source-identity/capabilities
```

It must not:

```text
run Source Intake
run iCloud acquisition
run cleanup
write DB rows
create Source Profiles
edit Source Profiles
persist endpoint identity
persist observed paths
persist probe results
write files to source paths
write marker files
copy files
delete files
mount or unmount drives
change drive letters
query credential stores
collect credentials
return or save raw command dumps
```

### 2. Source Type Model

Validation should use these probe-level source types:

```text
local
external_device
removable_media
nas
cloud
```

Do not change existing `ingestion_sources.source_type`.

### 3. Source Root Rules

For Local, External Device, and Removable Media:

```text
A Source Root may be a readable volume/media root, such as F:\,
or any readable folder below it.
```

For NAS:

```text
\\HENDERSON-NAS is a NAS server endpoint seed only.
It is not a runnable Source Root.

A runnable NAS Source Root must be a share or folder inside a share, such as:
\\HENDERSON-NAS\<share>
\\HENDERSON-NAS\<share>\<folder>
```

For Cloud:

```text
Generic source identity probe should not validate cloud credentials or sessions.
Cloud should return provider-specific / not generic probeable behavior.
```

### 4. Medium Confidence

For external/removable evidence:

```text
Partial evidence should generally produce needs_review, not automatic safe run.
```

This milestone should not decide future run policy beyond documenting actual response behavior.

### 5. Raw Evidence

The service/API must not return raw command dumps.

If raw-looking output appears, document as a bug/risk and do not include sensitive details in the closeout.

## Required Validation Cases

### 1. Capabilities Endpoint / Service

Validate:

```text
GET /api/admin/source-identity/capabilities
```

or equivalent service call.

Confirm response includes:

```text
os_family
supported providers
default provider
windows_non_admin_probe_v1
capability flags
limitations
```

### 2. Local Path Validation

Probe at least one local path.

Preferred:

```text
C:\
```

If a known local photo/test folder exists, also probe it. Do not create one.

Expected:

```text
source_type = local
filesystem_boundary_type = local_volume_root or local_folder
probe_status = completed or completed_with_warnings
path evidence present
host/volume evidence present or summarized
raw command dumps absent
```

Document whether `C:\` produces any broad-scan warning.

### 3. External Device Validation

If currently available, probe the external device paths.

Possible prior paths:

```text
D:\
E:\
```

Use only paths that currently exist and are ready.

Expected:

```text
source_type = external_device
filesystem_boundary_type = external_volume_root or external_folder
volume evidence present if available
device/PnP evidence present or partial
confidence_tier likely medium_needs_review unless strong evidence exists
safe_to_run likely needs_review or not_applicable
raw command dumps absent
```

If the device is not connected, document as unavailable and do not force it.

### 4. Removable Media Validation

If currently available, probe removable media.

Possible prior path:

```text
H:\
```

Expected:

```text
source_type = removable_media
filesystem_boundary_type = removable_media_root or removable_media_folder
media/volume/path evidence present if available
weak/partial evidence may produce needs_review
raw command dumps absent
```

If no SD/removable media is connected, document limitation.

### 5. NAS Server-Only Validation

Probe:

```text
\\HENDERSON-NAS
```

Expected:

```text
source_type = nas
filesystem_boundary_type = nas_server_only
is_valid_source_root_candidate = false
blocker includes nas_server_not_runnable
safe_to_run = false
clear next safe action says choose a share or folder inside a share
```

If the path returns access denied, this should still not be treated as proof that the NAS does not exist. It should be classified safely.

### 6. NAS Exact Share/Folder Validation

Only perform this if the user supplies a specific share/root path.

Examples:

```text
\\HENDERSON-NAS\Photos
\\HENDERSON-NAS\Photos\Family Archive
```

Expected if readable:

```text
source_type = nas
filesystem_boundary_type = nas_share_root or nas_share_folder
is_valid_source_root_candidate = true
path evidence readable
network share evidence present or summarized
raw command dumps absent
```

Expected if not readable:

```text
access_denied, path_not_found, path_not_readable, or credential_required
safe_to_run = false
no credential collection
no share enumeration
```

### 7. Cloud Generic Probe Validation

Probe a generic cloud request without credentials.

Expected:

```text
source_type = cloud
blocker or warning includes cloud_provider_not_probeable
no credential/session probing
safe_to_run false or not_applicable
response points to provider-specific readiness
```

### 8. Unsupported Provider Validation

Validate:

```text
os_family = linux
os_family = macos
unsupported provider_name
```

Expected:

```text
probe_status = unsupported_provider
safe_to_run = false
blocker includes unsupported_os_provider or provider_unavailable
no Linux/macOS commands attempted
```

### 9. Privacy / Redaction Validation

Inspect responses for:

```text
no raw command dumps
no full volume GUIDs
no full volume serials
no full PnP instance IDs
no credentials
no tokens
no session/cookie data
no full net use output
```

Document any concerns without pasting sensitive values.

### 10. Regression Test Validation

Rerun the relevant tests from 12.63.4.

Expected commands may include:

```powershell
..\.venv\Scripts\python.exe -m unittest discover -s tests -p "test_source_identity*.py"
```

Adjust paths to the project’s actual test execution convention.

If `pytest` is unavailable, use `unittest` as in `12.63.4`.

