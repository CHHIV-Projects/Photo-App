## 3. New Source Naming Behavior

For newly created filesystem Sources only:

- Entire Local/External endpoint defaults to `Entire device`.
- Entire NAS share defaults to `Entire share`.
- Non-empty endpoint-relative roots default to the final folder component.
- If another Source on the same endpoint already uses that short name, limited parent context is added.
- If all generated candidates collide, a short stable hash suffix is added as a final fallback.

Examples covered by tests:

- `Archive\Family Photos` -> `Family Photos`
- `Users\chhen\Pictures\Scans` -> `Scans`
- long External backup root ending in `2019-03-13` -> `2019-03-13`
- second same-endpoint `Photos` root under `Backup` -> `Backup - Photos`

The complete technical endpoint-relative root remains stored separately and visible in the normal UI as `Root Relative to Device`.

## 4. Whether Source Names Are Persisted, Derived, or Display-Only

For newly created filesystem Sources, the short Source Name is persisted as `IngestionSource.source_label`.

Existing, reused, adopted, or reactivated Sources retain their existing persisted labels. This milestone did not broadly migrate or rewrite previous Source labels.

## 5. Identity Wording Changes
