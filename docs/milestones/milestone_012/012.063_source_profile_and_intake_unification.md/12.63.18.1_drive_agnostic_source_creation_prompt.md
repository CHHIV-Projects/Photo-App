# 1. Goal

Implement **only Step 1 of the future Ingestion workflow**:

```text
Create a Source
```

Do not implement Source Selection.

Do not implement the selected-source Ingestion Workbench.

Do not change readiness, Source Intake launch, iCloud Intake, provenance, cleanup, Vault behavior, or the legacy source registry.

This milestone exists because the current Create Source flow still does not represent a filesystem source correctly.

For filesystem sources, the required model is:

```text
Source = Durable Device/Endpoint Identity + Root Relative to That Device
```

The current Windows drive letter must not be part of durable source identity.

---

# 2. Operator Flow

Use the supplied mockup as the flow guide.

Create one clearly visible box above the current Source Selector:

```text
Create a Source
```

Do not present creation only as a floating button.

Do not open a large unrelated management drawer before showing the normal fields.

Do not show duplicate Create Source buttons.

The normal non-iCloud flow is exactly:

```text
1. Choose Source Type.
2. Enter Device Name.
3. Enter or choose Root Path or Mount Point.
4. Press Create Source.
```

The operator selects the full current folder once.

The application—not the operator—must divide that full path into:

```text
Durable endpoint identity
Endpoint-relative root
Current observed path
```

# 4. Device Name

`Device Name` is free-form operator input.

Examples:

```text
Chuck PC
Henderson NAS
External 1
Family iCloud
```

Device Name is a human-readable alias.

It is not the durable identifier.

There should not also be a second required Source Label or Endpoint Alias field in the normal creation flow.

## Source display name

For filesystem sources, the system should derive the human-readable Source display name from:

```text
Device Name + endpoint-relative root
```

Examples:

```text
Chuck PC - Users\chhen\Pictures\Scans

External 1 - Archive\Family Photos

Henderson NAS - Dad Files\Scans
```

A shorter display label may be suggested later, but this milestone should preserve the full device/root relationship clearly.

---

# 5. Root Path or Mount Point

The operator enters the full path that is accessible now.

Examples:

```text
C:\Users\chhen\Pictures\Scans

E:\Archive\Family Photos

\\HENDERSON-NAS\Photos\Dad Files\Scans
```

The operator does not manually remove the drive letter.

The operator does not separately enter the endpoint root and relative root.

The system performs that split.

# 7. Local Source Creation

When Local is selected:

Normal inputs:

```text
Device Name
Root Path or Mount Point
```

Example input:

```text
Device Name:
Chuck PC

Selected path:
C:\Users\chhen\Pictures\Scans
```

The system must derive:

```text
Durable endpoint identity:
Volume GUID for C:

Endpoint-relative root:
Users\chhen\Pictures\Scans

Current observed path:
C:\Users\chhen\Pictures\Scans
```

The durable identity is the Volume GUID, not `C:`.

The endpoint-relative root must not include `C:\`.

A UNC path must not be accepted as Local.

Suggested message:

```text
This is a network path. Choose NAS.
```

# 8. External Source Creation

When External is selected:

Normal inputs:

```text
Device Name
Root Path or Mount Point
```

Example input:

```text
Device Name:
External 1

Selected path:
E:\Archive\Family Photos
```

The system must derive:

```text
Durable endpoint identity:
Volume GUID for the external volume

Endpoint-relative root:
Archive\Family Photos

Current observed path:
E:\Archive\Family Photos
```

The durable identity is the Volume GUID, not `E:`.

The endpoint-relative root must not include `E:\`.

## Drive-letter independence

A Source created while the external volume is assigned `E:` must not be defined as an `E:` source.

The stored durable source model must be:

```text
Device:
Volume GUID {...}

Root:
Archive\Family Photos
```

The full `E:\Archive\Family Photos` path may be retained as initial observed-path or compatibility evidence, but it must not be the durable source definition.

Actual runtime re-resolution after the drive later becomes `F:` is **not implemented in this milestone**. That will be the next focused milestone.

This milestone must create and persist the data required for that later resolution.

# 9. NAS Source Creation

NAS must be a separate user-facing type.

When NAS is selected:

Normal inputs:

```text
Device Name
Root Path or Mount Point
```

## Direct UNC example

Input:

```text
Device Name:
Henderson NAS

Selected path:
\\HENDERSON-NAS\Photos\Dad Files\Scans
```

The system must derive:

```text
Durable endpoint identity:
\\HENDERSON-NAS\Photos

Endpoint-relative root:
Dad Files\Scans

Current observed/canonical path:
\\HENDERSON-NAS\Photos\Dad Files\Scans
```

The durable NAS endpoint is server + share.

The selected root may be any depth below that share.

Do not shorten a deeply selected test root to only its first folder.

## Mapped NAS path

A mapped drive may be entered, such as:

```text
Z:\Dad Files\Scans
```

The app must attempt read-only mapping resolution.

If it resolves to:

```text
\\HENDERSON-NAS\Photos\Dad Files\Scans
```

then derive:

```text
Endpoint:
\\HENDERSON-NAS\Photos

Endpoint-relative root:
Dad Files\Scans

Original observed path:
Z:\Dad Files\Scans
```

If the mapping cannot be resolved:

```text
Do not create it as Local.
Do not create it as External.
Do not create an ambiguous NAS source.
Ask the operator to enter the UNC path.
```

Do not request credentials.

Do not create or alter drive mappings.

# 13. Data Model Requirements

This milestone must persist the distinction between:

```text
Durable endpoint identity
Endpoint-relative root
Current observed path
Source Profile
```

For new Local and External sources, persist:

```text
endpoint link
endpoint-relative root without drive letter
initial observed full path
free-form Device Name
operator source type
```

For new NAS sources, persist:

```text
endpoint link based on server/share
root relative to server/share
canonical UNC full path
original mapped path as observed evidence when applicable
free-form Device Name
operator source type
```

An additive schema field such as:

```text
endpoint_relative_root
```

or an equivalent normalized field is approved and expected if it does not already exist.

Do not destructively replace existing fields.

Do not migrate existing Source Profiles in this milestone.

Existing profiles remain untouched.

# 14. Endpoint Reuse

When the selected location identifies an existing durable endpoint:

```text
Reuse the existing endpoint.
Create a new Source Profile for the selected relative root.
```

Example:

```text
Existing endpoint:
Henderson NAS / \\HENDERSON-NAS\Photos

New source root:
Dad Files\Scans
```

This is not a duplicate error.

Normal wording:

```text
Existing device identity found.
A new source will be created for the selected root.
```

When exactly one strong match exists and there are no blockers, the Create Source action is sufficient confirmation.

Do not require a second ominous warning checkbox.

Require review only for:

```text
multiple matches
ambiguous identity
Not verified identity
real blockers
```

# Whole Device / Whole Share Source

The operator may choose the endpoint root itself rather than a subfolder.

Examples:

Local:
  C:\

External:
  E:\

NAS:
  \\HENDERSON-NAS\Photos

When the selected location equals the endpoint boundary:

- endpoint_relative_root must be stored as an empty string
- empty string means intentionally scan the entire device/share
- NULL remains reserved for legacy, unknown, or unresolved roots
- the full current path remains observed-path evidence
- the normal UI should display:
    Entire device
    or
    Entire share

For NAS, the whole-source boundary is the selected share, not the NAS server.
A server-only path such as \\HENDERSON-NAS remains invalid.

The Create Source UI may support either:

- selecting the device/share root directly in the path field, or
- an explicit “Scan entire device/share” choice that fills the endpoint root

Do not require the operator to enter a fake slash, dot, or placeholder relative root.

If another Source on the same endpoint overlaps the whole-device/share source,
show a non-blocking overlap warning.
