## 2. Implementation Summary

12.66.8 extended the existing Windows Helper provider with bounded mounted-volume observation for External and Removable Sources. The Helper observes Windows-local mounted-volume facts; the backend retains authority for durable Endpoint matching, exactly-one-match enforcement, Profile-relative-root resolution, readiness, acquisition, and ingestion.

The final implementation also corrects cross-acquisition prior-observation matching so a transient runtime drive-root change does not create duplicate Provenance. Durable matching now requires the same provider, Endpoint ID, Profile ID, durable run/item fingerprints, normalized Profile-relative path and digest, and independently verified SHA-256.

## 27. Deviations

- Helper 0.5.0 could not observe mounted Windows volume identity after Linux lost direct Windows visibility, so the explicitly approved narrow 0.5.1 capability was required.
- The original `Get-Volume` subprocess approach proved unsuitable: it could exceed even a 30-second Python timeout. It was replaced by bounded native drive enumeration plus `mountvol <drive> /L`, preserving the existing fingerprint model.
- Early installation validation exposed PowerShell process exit-code capture behavior; the exact version check was preserved and moved to `System.Diagnostics.Process` capture.
- The initial External root exceeded the controlled inventory limit; validation stopped and resumed only with the Product Owner-approved contained `XnSketch` root.
- The External unchanged repeat exposed the transient-root lineage defect. Duplicate Provenance reconciliation was performed only after explicit Product Owner authorization, as documented in section 13.
- The first unscoped broad pytest command collected an experimental script and failed collection because optional `pyicloud` was absent. The correctly scoped comprehensive `backend/tests` run produced the accepted 692/1 baseline result.
