# 9. Remote Operation Contract

Do not create arbitrary RPC or remote command execution.

Helper operations must be closed, typed, versioned protocol messages.

12.66.3 requires only conceptual operations equivalent to:

probe_source
inventory_page

A Helper request must never contain:

shell command
PowerShell text
arbitrary executable
SQL
Linux filesystem path authority
Vault path
Docker command

The Helper decides how its established collector performs an allowed operation internally.

Linux decides which operation is authorized.

# 10. Operation State

Because the Helper initiates communication outbound, implement the smallest reliable claim/result mechanism needed to bridge Linux requests to the foreground Helper.

A narrow durable Helper-operation record is authorized if required.

If added, it should conceptually contain only bounded state such as:

operation ID
Access Node ID
operation type
request payload
state
created / claimed / completed / expired timestamps
result payload or safe error
attempt/lease information if required

Do not turn this into a generic job framework.

Do not add acquisition-run/item state.

Required properties:

- operation bound to exact authenticated AccessNode;
- another Helper cannot claim it;
- one operation cannot be completed twice with conflicting results;
- expired/stale claim fails safely;
- unknown operation type fails closed;
- result payload validated before application use;
- no secret material persisted in request/result.

If durable operation state cannot be added without materially expanding the schema beyond this bounded purpose, stop and report.

# 15. Durable Identity Rules

Preserve all existing rules.

For Local / External / Removable:

- durable volume/device identity is authoritative;
- drive letter is observation/location only;
- same durable volume at another letter remains same device identity;
- different durable volume at same letter must fail closed against enrolled identity.

For Windows NAS:

- mapped drive resolves to canonical UNC identity;
- do not promote Windows Helper NAS over the accepted Linux Mounted provider where Linux already has legitimate direct access.

For Optical:

- accepted Optical v2 disc/media fingerprint semantics remain unchanged.

Do not weaken identity evidence merely to make remote creation succeed.

- explicit;
- bounded;
- paginated;
- deterministic enough for controlled continuation;
- rooted strictly beneath the authorized Profile root;
- non-mutating.

Do not use "whole machine" or drive discovery.

# 23. Inventory Safety

Inventory must reject or safely classify:

- traversal outside root;
- symlinks/reparse points where unsafe under current Source rules;
- device/special files;
- inaccessible entries;
- unsupported path forms;
- root identity change during operation.

Use existing Source-selection/media eligibility semantics where practical.

Do not silently follow a Windows junction/reparse point outside the authorized root.

If current Windows semantics make safe containment ambiguous, fail the candidate/root rather than broadening access.

---

# 24. Inventory Paging / Bounds

Define explicit bounded constants.

Do not return an unbounded recursive manifest in one Helper response.

Use a conservative page-size maximum suitable for JSON control traffic.

The exact constant may follow repository evidence, but must be:

- fixed or server-bounded;
- tested;
- rejected if client asks above maximum.

Continuation/cursor state must be opaque and validated.

A cursor must not allow changing:

AccessNode
Profile/root
Source identity
inventory generation

without failing closed.

Do not prematurely define transfer chunks or acquisition resume semantics.

---

# 25. Inventory Consistency

12.66.3 does not need to solve a perfect immutable Source snapshot.

It does need enough consistency evidence to detect obvious mutation between pages.

Use the smallest appropriate generation/root evidence, such as:

- inventory generation ID;
- durable Source fingerprint;
- authorized normalized root;
- bounded root/generation metadata.

If the Source identity changes while paging, stop that inventory.

If a candidate changes later during acquisition, 12.66.4 will revalidate it before trusting bytes.

Do not overengineer a filesystem snapshot system.
