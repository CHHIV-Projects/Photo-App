## 2. Implementation Summary

The Windows acquisition bridge maps only a completed, verified `SourceAcquisitionRun` into the ordinary common Source Intake pipeline through `PipelineContext.explicit_source_records`. It does not scan the receiving tree or add a second ingestion engine.

The implementation adds the smallest optional Windows Asset-lineage field, provider-neutral durable bridge links, and explicit-record-only ordering. Existing providers fall back to their prior behavior.

## 3. Acquisition-to-Source-Intake Bridge

- `GET /api/admin/source-acquisitions/{run_id}/bridge` performs read-only planning/reverification.
- `POST /api/admin/source-acquisitions/{run_id}/bridge/execute` performs trusted backend-only launch.
- The bridge creates an ordinary `SourceIntakeRun` and uses the ordinary `IngestionRun` and common pipeline.
- The Windows Helper receives no Asset, Vault, Provenance, or database authority.

## 4. Explicit Candidate Mapping

Each retained acquisition item maps to one explicit record containing the opaque Linux ready path, Windows-native Asset-lineage evidence, and durable acquisition ordinal as `explicit_order`. The item query is ordered by ordinal. Explicit order survives Drop Zone staging, batching, hashing, deduplication, and first Asset creation. Ordinary recursive records have no explicit order and retain existing path ordering.
