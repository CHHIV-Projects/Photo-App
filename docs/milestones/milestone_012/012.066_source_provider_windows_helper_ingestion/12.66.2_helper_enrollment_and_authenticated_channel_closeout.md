## 3. Credential Schema

Two additive tables are created through the repository's idempotent startup schema convention:

- `windows_helper_credentials` — public credential ID, Access Node foreign key, credential version, domain-separated token digest, status, creation/rotation/revocation/last-use timestamps;
- `windows_helper_pairing_authorizations` — public pairing ID, Access Node foreign key, domain-separated secret digest, state, expiry, and consumption timestamp.

The Access Node relationship is unique in the credential table, so a Helper has one durable credential row. Raw credential and pairing secrets are not persisted in PostgreSQL.

Machine-generated secrets use `secrets.token_urlsafe(32)`, providing at least 256 bits of entropy. Linux stores deterministic, domain-separated SHA-256 digests and compares them with `hmac.compare_digest`.

## 8. Authentication Model

The authorization scheme is:

```text
Authorization: PhotoOrganizerHelper <public credential ID>.<high-entropy secret>
```

The public ID selects the single credential row. The supplied secret is domain-separated, hashed, and constant-time compared with the stored digest. Missing, malformed, unknown, wrong, or revoked credentials fail with `401` and do not fall through to another authority.

Credential rotation atomically changes the public ID, version, and digest in the single Access-Node-bound row and invalidates the prior value.

## 10. SSH Forwarding Model

The exact accepted forward is:

```text
Windows 127.0.0.1:18011
→ henderson-server1 over OpenSSH
→ Linux 127.0.0.1:18011
```

The Helper requires the exact Windows OpenSSH executable, current-user ownership for a reused listener, exact arguments, exact loopback addresses, strict host-key verification, `BatchMode=yes`, `ExitOnForwardFailure=yes`, bounded keepalive, `GatewayPorts=no`, `PermitLocalCommand=no`, `-N`, and `-T`. Remote and dynamic forwarding are rejected.

Effective SSH configuration is inspected with non-connecting `ssh -G`; configuration-injected local, remote, or dynamic forwards fail closed. The existing operator forward on 18001 is neither reused nor modified.

The initial Windows validation revealed that `Get-NetTCPConnection` could exceed the ten-second listener-inspection budget even with no listener. The corrected implementation obtains the bounded listener row with `netstat.exe`, retains owner/executable/command-line validation when a listener exists, and converts inspection failures into a generic fail-closed `TunnelError`. The corrected wheel passed live tunnel preflight.
