# Milestone 12.66.9.4 — iCloud Source Path Authority and Interactive Authentication

## Purpose

Complete two remaining iCloud provider gaps discovered during Product Owner ingestion testing:

1. iCloud Source creation currently allows the browser to fabricate an environment-specific backend staging path, which can create a Profile that is invalid immediately after creation.

2. When iCloud authentication is stale or missing, normal operation still depends on an external terminal-based `icloudpd --auth-only` workflow. Replace that operator workaround with a bounded in-application authentication experience.

This milestone should produce a normal user flow:

Create iCloud Source
→ backend derives canonical staging location
→ Source saves in an immediately valid state
→ Source selection/readiness checks authentication
→ if authentication is stale, Photo Organizer opens an in-app sign-in dialog
→ user supplies required authentication/MFA interaction
→ backend refreshes protected iCloud session state
→ readiness automatically reruns
→ original user action can continue
→ iCloud acquisition still feeds the existing common Source Intake

Do not redesign the iCloud acquisition engine or create a second ingestion path.

# 6. Locked Path-Authority Rule

Environment-specific runtime filesystem paths belong to the backend runtime configuration.

The browser may display such a path.

The browser must NOT derive or authoritatively submit such a path for ordinary iCloud Source creation.

For normal creation, the backend must derive the canonical staging root from:

configured EXPORTS_ICLOUD_PATH
+
a deterministic sanitized Source/Profile slug or other accepted repository naming contract

Conceptually:

managed_staging_path =
configured EXPORTS_ICLOUD_PATH / canonical_source_slug

Where the current model requires alignment:

source_root_path
=

managed_staging_path
=

expected acquisition/staging root

The exact current model should be preserved unless an existing accepted invariant requires a distinction.

---

# 7. Canonical Path Derivation

Implement one backend authority for canonical iCloud staging-path derivation.

Requirements:

- derives from backend configuration;
- deterministic;
- contained beneath configured iCloud exports root;
- no browser-selected arbitrary host/container path;
- no traversal;
- no symlink escape;
- no absolute user-provided path;
- no dependence on frontend working directory;
- no dependence on Windows paths;
- safe slug collision handling.

If a canonical path cannot be derived safely:

Source creation must fail BEFORE durable Profile persistence.

Do not save a Profile that is guaranteed to fail its first selection/readiness check.
