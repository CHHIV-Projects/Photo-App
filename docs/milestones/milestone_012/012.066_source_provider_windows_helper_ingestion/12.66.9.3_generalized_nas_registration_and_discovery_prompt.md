# Milestone 12.66.9.3 — Generalized NAS Registration and Discovery

## Purpose

Replace the current single-share-specific NAS implementation with a safe generalized NAS registration model that can support:

- more than one NAS appliance;
- more than one registered share/location;
- bounded NAS discovery as a convenience;
- explicit host entry when discovery is unavailable;
- stable registered NAS/share identity that is not based on IP address alone;
- secure server-side credential and mount handling;
- the existing Source Endpoint/Profile and common-ingestion architecture.

This milestone is about NAS registration and access.

It must NOT redesign ingestion.

The desired normal user flow is:

NAS
→ discover or explicitly identify NAS
→ explicitly register NAS/share
→ choose registered NAS location
→ choose bounded folder
→ enter Source Profile name
→ Review Source
→ save/reuse Endpoint/Profile
→ select and ingest through the existing workflow

Discovery is advisory.

Registration and verified server-side access are authoritative.

# 10. Durable NAS Identity Requirement

+

+
share

same IP
=

Use a layered model:

application-generated immutable NAS registration ID
+

+

- share path string alone

different registered share

→ require explicit user/admin confirmation or block according to safe design

# 14. NAS Discovery

Add bounded advisory discovery if it can be implemented safely and reliably.

Candidate mechanisms may include:

- mDNS / DNS-SD;
- WS-Discovery;
- bounded SMB-advertised discovery available through existing Linux tools/libraries.

Do NOT implement:

- unbounded subnet scanning;
- generic port scanning;
- Internet-wide discovery;
- discovery that automatically mounts or registers a NAS.

Discovery must:

- be explicitly user-triggered;
- have bounded timeout;
- return a bounded candidate list;
- expose browser-safe names/address hints only;
- perform no durable mutation;
- create no credentials;
- create no mount;
- create no Source.

A discovered candidate remains untrusted until explicit registration succeeds.
