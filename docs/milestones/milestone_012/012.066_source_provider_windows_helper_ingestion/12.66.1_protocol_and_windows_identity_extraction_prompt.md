# 11. Protocol Safety Rules

The protocol models must:

- reject unknown fields unless a deliberate compatibility reason is documented;

- enforce explicit bounded string/list sizes where practical;

- use explicit enums/status vocabularies rather than arbitrary free text for machine decisions;

- keep user-display text separate from machine authority;

- contain no Linux receiving-path field in this milestone;

- contain no Vault/database path field;

- contain no generic command-execution field;

- contain no generic arbitrary-file-upload field;

- serialize deterministically where a canonical digest is required;

- remain transport-neutral.

HTTP/JSON may be the future transport, but the protocol must not depend on a live HTTP layer.

# 12. Provider-Native Path Contract

Freeze the terminology in code/tests.

At minimum distinguish:

```text
provider_native_root
provider_native_relative_path
provider_native_full_path
```

For this milestone:

- all are Windows-native strings;

- no value is converted to POSIX;

- no value is joined into a Linux path;

- full path must be derivable/checkable from root + relative path according to Windows rules;

- path containment must be explicit;

- `..`, cross-volume escape, ambiguous roots, and invalid path forms fail closed.

If current code already has better established names, reuse them consistently and document the mapping in the closeout.

Do not introduce redundant synonyms.
