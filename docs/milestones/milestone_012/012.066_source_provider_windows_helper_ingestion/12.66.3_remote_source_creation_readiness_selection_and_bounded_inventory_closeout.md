## 3. Remote Operation Model

The application creates one typed operation (`probe_source` or `inventory_page`) and returns immediately. The authenticated Helper polls the isolated Helper API, claims only an operation bound to its Access Node, executes the recognized operation, and completes or fails it with a validated bounded result. The application polls and consumes the immutable completed result.

Operation state is durable control metadata with pending, claimed, completed, failed, and expired states. Development timing defaults are 10 minutes pending expiry, 6 minutes claim lease, 30 seconds heartbeat, 90 seconds offline threshold, 2 seconds Helper polling, and 5 minutes completed-probe freshness for readiness/selection/inventory.

## 4. Protocol Additions

The shared strict protocol now defines:

- typed probe and inventory operation envelopes;
- exact Access Node, Endpoint, Profile, Source type, and provider-native path bindings;
- bounded inventory item kinds (`regular_file`, `reparse_point`, `special`, and `inaccessible`);
- metadata-only item evidence, inventory generation, and opaque continuation cursor;
- strict completion, failure, heartbeat, and operation-claim messages;
- default page size 50, maximum page size 100, and maximum serialized result size 1 MiB.

Unknown fields and unsupported operation/version values fail validation.
