## 2. Implementation Summary

Implemented the narrow provider-neutral orchestration and repeat-observation behavior required to carry a Windows Helper Source from normal Run Ingestion dispatch through bounded acquisition, verified receiving, and common Source Intake.

The implementation:

- recognizes `windows_helper_intake` in Run Ingestion dispatch;
- keeps Windows Profiles free of fabricated Linux mounted roots;
- creates a first bounded Helper inventory operation through the normal dispatcher;
- provides a thin, stateless acquisition-advance facade over existing durable operations;
- revalidates every received object before bridge execution;
- supports first-run common Source Intake and fully reused unchanged repeats;
- preserves Windows-native Asset lineage separately from opaque Linux Runtime Root/Provenance evidence.

No second ingestion engine, new orchestration table, Helper authority expansion, or Windows-specific Asset/Provenance column was introduced.

## 3. End-to-End Orchestration Model

The accepted flow is:

`Source Selection → Run Ingestion dispatch → bounded inventory → acquisition plan/approval → serialized Helper acquisition → Linux receiving verification → bridge classification → common Source Intake when required → completed workflow`

The new `advance` facade uses existing durable acquisition and Helper-operation state. It authorizes at most the next exact acquisition item, reports `awaiting_helper` while work is outstanding, invokes the accepted bridge only after acquisition completion, and returns the existing completed bridge result idempotently.
