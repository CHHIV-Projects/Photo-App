# Milestone 12.66.9.5 — Windows Portable Source Reconciliation

## Purpose

Complete the remaining Windows External/Removable ingestion gaps discovered during Product Owner testing.

Two defects are in scope:

1. Portable Source creation currently conflates a device-relative folder with a complete Windows path. Entering a drive-qualified folder such as `E:\Chuck Iphone` can produce a malformed composed path and surface HTTP 500.

2. Windows Helper inventory/acquisition currently treats its 100-item page/transfer bound as a whole-Source limit. A Source with more than 100 candidates is therefore blocked even though Photo Organizer's canonical ingestion architecture is intended to process one logical Source ingestion through successive bounded batches/chunks.

This milestone must reconcile Windows portable acquisition with the architecture already demonstrated by iCloud:

User approves one Source ingestion
→ backend owns one durable parent workflow
→ provider access/inventory occurs in bounded pages
→ transfer/acquisition occurs in bounded chunks
→ common Source Intake processes each verified chunk
→ backend aggregates progress/results
→ one logical ingestion completes

For a Source containing 267 eligible assets, the expected Windows portable transport shape is conceptually:

100 + 100 + 67

The user should experience one 267-asset ingestion, not three unrelated ingestions.

# 7. Portable Path Contract

For External and Removable creation, the browser must not construct the authoritative Windows full path.

Change the portable creation contract to conceptually submit:

discovery_candidate_token
+
endpoint_relative_root

The backend must:

1. resolve the verified discovery candidate;
2. obtain the authoritative current device root from the completed Helper observation;
3. validate the relative component independently;
4. construct the provider-native full Windows path;
5. prove containment beneath the observed device root;
6. persist only the resulting accepted provider-native Source contract.

Use repository naming conventions.

Do not alter the Windows Local absolute-folder contract unless a shared schema must be separated to preserve type safety.

# 8. Discovery Candidate Token

It should bind sufficiently to:

- AccessNode/current route where needed;
- Source type;
- durable Endpoint/device fingerprint;
- current observed root;

- candidate identity.

The browser must not be able to alter:

- durable fingerprint;
- authoritative root;
- provider type;
- device classification.

If the candidate is stale, expired, disconnected, or no longer matches the durable device:

fail closed and require rediscovery.

# 9. Relative Folder Validation

- empty value = device root;

- spaces;

- UNC path;
- leading absolute separator;
- colon / alternate data stream syntax;
- `.` / `..` traversal where unsafe;
- empty unsafe intermediate components;
- invalid Windows path syntax;
- path that escapes the observed root.

Chuck Iphone
Photos\2026
Family Photos

Invalid:

E:\Chuck Iphone
\\server\share
\Chuck Iphone
..\Photos
Photos\..\..
file:stream
