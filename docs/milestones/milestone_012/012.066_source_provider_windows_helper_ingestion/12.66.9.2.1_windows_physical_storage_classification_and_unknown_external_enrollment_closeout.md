## 4 Windows Evidence Sources

Raw hardware identifiers remain local to the Helper and do not cross the protocol boundary.

## 5 Physical Storage Classification Policy

The backend remains authoritative and classifies fail closed. Evidence must be structurally valid, internally consistent, and sufficient for the requested Source type. Zero, multiple, malformed, contradictory, offline, or unknown associations are excluded rather than guessed.

Volume GUID v2 matching still controls known Endpoint reuse and wrong-device protection. Storage evidence does not replace identity matching.

## 6 USB HDD / SSD Classification

A new External candidate requires all of the following:

- Windows `fixed` presentation;
- exactly one partition and exactly one backing physical disk;
- disk device class;
- supported externally attached bus/topology evidence (`usb` or `ieee1394` in this implementation);
- consistent external-connection evidence;
- online operational state; and
- neither boot nor system disk.

The live USB fixed disk met this policy and was eligible for first-time External enrollment.

## 7 Removable Classification

Windows `removable` presentation remains the primary Removable route. Helper protocol v1 remains compatible for known devices unless newer evidence contradicts it. Under protocol v2, contradictory physical evidence fails closed.

A new Removable device was detected and enrolled through the normal UI flow after the bounded request-shape correction.

## 8 Optical Exclusion

Optical presentation/device evidence is excluded from External and Removable discovery. Optical remains a separate future provider path and cannot be enrolled through these controls.

## 9 Virtual / Cloud Exclusion

Fixed presentation alone is insufficient. A volume without an exact physical partition/disk association is not a new External candidate. The live Google Drive root therefore remained ambiguous and excluded. No Google Drive provider or heuristic exception was added.

## 10 Network Exclusion

Remote/network drive presentation is excluded from External and Removable classification. Network storage is not converted into a physical Windows Source Endpoint.

## 11 Internal Storage Exclusion

Boot disks, system disks, and supported internal-bus disks are excluded from unknown External enrollment. The live NVMe system disk was correctly classified as internal and excluded.

## 12 Thunderbolt / USB4 Handling

The classifier supports only positive topology it can prove with the closed protocol vocabulary. USB and IEEE 1394 are positively supported. Thunderbolt/USB4 devices whose exposed evidence does not map unambiguously to an accepted external topology fail closed. No drive-letter, vendor-name, or filesystem heuristic was introduced.

- A fixed-presentation USB flash device may be classified as External because the accepted policy is verified externally attached fixed media, not vendor/media-name heuristics.
- Ambiguous or unavailable Windows storage associations remain excluded even when a human believes a device is physical.
- Windows hostname suggestion remains deferred and is not durable AccessNode identity.
- Optical, cloud/virtual, and network storage remain separate provider concerns.
- Stronger physical-computer fingerprinting remains outside this milestone.
