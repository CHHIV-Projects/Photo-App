## 5. NAS Namespace Startup / Recovery Root Cause

At boot, `/mnt/nas/photo-organizer` can initially have only its exact configured `autofs` row while the authoritative CIFS mount is not yet active. The historical namespace script required the CIFS row immediately, classified this normal readiness interval as a permanent identity failure, and caused the oneshot namespace unit to fail. The broker correctly remained unavailable because it requires the namespace unit.

## 6. NAS Reliability Correction

The namespace script now distinguishes only two accepted authority states:

- exact active authority: one configured `autofs` row plus one canonical CIFS row;
- exact inactive authority: one configured `autofs` row and no other row.

For the exact inactive state, the script performs one bounded read-only `stat` of the authoritative target to activate the configured automount, then rereads the mount table and applies the existing strict source, filesystem, uniqueness, major/minor, and propagation checks. Wrong, duplicate, or conflicting evidence still fails closed without repair. A temporary automount delay exits with status 75; strict identity failures retain status 1.

The unit now orders after and wants network-online, retries transient failures after 15 seconds, and suppresses retry for strict status-1 failures. No NAS ownership, permissions, content, mount configuration, or authoritative identity was changed.
