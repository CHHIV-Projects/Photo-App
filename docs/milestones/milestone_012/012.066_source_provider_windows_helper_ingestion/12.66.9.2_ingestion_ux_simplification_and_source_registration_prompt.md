# Milestone 12.66.9.2 — Ingestion UX Simplification and Source Registration

The provider architecture is already technically accepted.

AccessNode
→ SourceEndpoint
→ Source Profile / IngestionSource
→ provider readiness/acquisition
→ common Source Intake

This is primarily a UX simplification and bounded routing/invariant milestone.

- Source Endpoint/Profile architecture;
- Windows Helper security/pairing protocol;
- Mounted Source Provider;
- common Source Intake;
- iCloud;
- Vault/provenance;

# 13. Local Endpoint Invariant

Implement the 12.66.9.1 service-level invariant for new normal-flow creation.

For the selected registered Windows computer:

ZERO active Local Endpoints observed
→ permit creation only after existing strong Volume GUID and containment checks pass.

EXACTLY ONE active Local Endpoint with the same durable volume fingerprint
→ reuse the Endpoint and create/reuse the requested Profile.

EXACTLY ONE existing Local Endpoint but a different local-volume fingerprint
→ fail closed with a clear user-facing result such as:

"Additional local volumes are not supported in this version."

MULTIPLE active Local Endpoints
→ fail closed for operator review.

Do not automatically choose one.

Do not rewrite existing Endpoints.

Do not add a simplistic uniqueness constraint using only created_from_access_node_id.

The invariant belongs in the appropriate creation/service authority.

# 16. External Definition

External
=

a durable externally attached storage device.

Its Endpoint identity belongs to the physical device.

It is NOT owned by the Windows computer currently providing access.

Requirements:

same physical External device
connected through another registered computer
→ same Endpoint

drive-letter change
→ same Endpoint

different device at same drive letter
→ different identity / fail closed

Do not display the Windows computer as part of normal External Source creation.

---

# 17. Removable Definition

Apply the same principles to Removable.

Removable Endpoint identity belongs to the durable physical removable device.

The observing Windows computer is only an access route.

Do not require normal users to select the computer.

# 19. Portable Source Cross-Computer Routing

The current durable model already permits one Endpoint to have observations from multiple AccessNodes.

Correct the runtime route resolution.

For an already matched External/Removable Endpoint:

ZERO currently valid online matching Helper routes
→ Source remains visible;
→ unavailable state;
→ Run disabled.

EXACTLY ONE currently valid online matching Helper route
→ select automatically.

MORE THAN ONE currently valid online matching Helper route
→ do not choose automatically;
→ fail closed into an exceptional route-selection state.

Historical observations alone must NOT count as currently online routes.

Require current:

- active AccessNode;
- valid paired credential/state;
- current Helper availability/heartbeat;
- current verified observation of the same durable fingerprint.

Use existing authorities where possible.
