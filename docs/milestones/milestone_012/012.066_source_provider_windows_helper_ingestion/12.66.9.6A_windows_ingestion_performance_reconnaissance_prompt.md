# Milestone 12.66.9.6A — Windows Ingestion Performance Reconnaissance

## Purpose

Determine, with measured runtime evidence, why Windows Local / External / Removable Source processing is currently much slower than expected.

This is a PERFORMANCE RECONNAISSANCE milestone.

Do not optimize product behavior yet.

The Product Owner specifically observes two long user-visible phases:

1. `Checking Sources`
2. actual ingestion after approval

The immediate questions are:

- What exactly occurs in each phase?
- How much wall-clock time is consumed by each operation?
- Which work is repeated between the two phases?
- Which work is necessarily repeated for identity/integrity?
- Which work is unnecessarily repeated?
- How much time is actual Windows disk I/O?
- How much is hashing?
- How much is Helper physical-device verification?
- How much is Helper/backend communication?
- How much is polling/sleep/wait time?
- How much is actual Helper → Linux byte transfer?
- How much is Linux verification/common Source Intake?
- Are files being read or hashed more times than necessary?
- Can the backend provide already-known authoritative information to Helper so Helper verifies rather than rediscovers it repeatedly?
- Which optimizations appear likely to provide the largest benefit without weakening Source identity, transfer integrity, Vault integrity, or Provenance?

12.66.9.6A ends with measured findings and recommendations.

NO throughput optimization is authorized in this milestone.

There must be a hard Product Owner review before 12.66.9.6B implementation.
